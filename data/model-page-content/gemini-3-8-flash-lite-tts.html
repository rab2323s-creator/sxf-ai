What is Gemini 3.8 Flash-Lite TTS?

Gemini 3.8 Flash-Lite TTS is Google's production text-to-speech model for cost-efficient, low-latency voice generation at scale. It turns a supplied text transcript into speech audio, using selectable voices and structured delivery instructions. Google positions Flash-Lite for bulk narration, read-aloud features, voice replication and conversational voice-agent pipelines.

The exact Gemini API model ID is gemini-3.8-flash-lite-tts. It accepts text input and returns audio output, with an 8,192-token input limit, a 16,384-token output serving limit, and support for 101 languages. It is not the general-purpose Gemini 3.8 Flash reasoning model or the bidirectional Gemini Live API.

Choose Flash-Lite when you need many usable audio clips at controlled cost. Choose Gemini 3.8 Flash TTS when premium vocal fidelity, subtle acting, difficult pronunciations or broad regional-dialect coverage matter more than unit price. The two Gemini 3.8 TTS variants share the same request schema, making side-by-side testing straightforward.

MODEL CHOICE BY PRODUCT

What should you use Gemini 3.8 Flash-Lite TTS for?

Google positions Lite for high throughput and latency sensitivity, but the actual choice must be validated on your languages, voice identities and scripts.

01 · AUDIO ARTICLES

News and read-aloud features

Generate narration on demand for articles, product descriptions and accessibility-oriented reading experiences. Use clear punctuation and a stable voice, and evaluate difficult names, abbreviations and numerals before publishing.

02 · LARGE CONTENT LIBRARIES

Training and e-learning audio

Turn reusable course lessons into speech at a predictable per-minute output rate. Separate chapters into coherent segments, maintain transcript/version alignment and spot-check pronunciation in every supported locale.

03 · VOICE AGENT CASCADES

Speech after an agent produces text

For a pipeline that uses a separate recognition/LLM stage and then synthesizes a reply, Flash-Lite is a price/latency-oriented output component. It is not itself the bidirectional Gemini Live API.

04 · NOTIFICATIONS AND IVR

Personalized speech at volume

Generate short prompts and branded notifications with clear delivery settings. Define fallbacks for failures, invalid input and unavailable capacity. For telephony, confirm audio format and sample-rate compatibility.

05 · VOICE DESIGN WORKFLOWS

Consistent brand voice

Use Google's voice library and voice-design ecosystem for consistent narrators. Replication requires appropriate permission and handling of people's identities; test quality and consent procedures carefully.

06 · REGIONAL AND CREATIVE AUDIO

Know when to move to Flash

Switch to Flash TTS for premium audiobooks, unusually difficult pronunciation, subtle emotional acting, or dialects beyond Lite's documented language support. Evaluate both variants using the same test script.

How to choose between the two TTS variants

  1. Define an acceptance test. Pick representative voices, numerals, language samples, long passages and emotional delivery instructions.
  2. Run the same script on both models. Use the same voice and style where supported, and record audio quality, generation time and failure/retry frequency.
  3. Calculate full production economics. Include actual audio seconds, text input, service tier, failed requests and any post-processing.
  4. Start with Lite when quality passes. Escalate specific creative or dialect-heavy segments to Flash rather than paying the premium for every clip.

COPYABLE GEMINI API CODE

How to generate a WAV file with Gemini 3.8 Flash-Lite TTS (Python).

Google's documented Interactions API supports both 3.8 TTS variants. Use gemini-3.8-flash-lite-tts for Lite, and switch just the model value to A/B test Flash TTS.

import base64
from google import genai

client = genai.Client()  # Set GEMINI_API_KEY in the environment
result = client.interactions.create(
    model="gemini-3.8-flash-lite-tts",
    input=[{
        "type": "user_input",
        "content": [{
            "type": "text",
            "text": "Your delivery is arriving this afternoon.",
            "annotations": [{
                "type": "speech_metadata",
                "style": "clear, warm and helpful",
            }],
        }],
    }],
    response_format={"type": "audio"},
    generation_config={
        "speech_config": [{"voice": "Kore"}],
    },
)

with open("lite-tts-output.wav", "wb") as audio_file:
    audio_file.write(base64.b64decode(result.output_audio.data))

Installation: install Google's maintained google-genai SDK and follow its current version requirements for Gemini 3.8 TTS. Keep the API key server-side. The example uses speech_metadata.style to specify delivery; spoken words remain in the text field. Official example and SDK guidance ↗

1 / SELECT A VOICE

Prebuilt or designed

Kore and other supported voices can be chosen through speech_config. Different personas should be tested for each language and deployment.

2 / STRUCTURE PERFORMANCE

Speech metadata

Put sustained emotion, delivery and pace instructions in structured speech_metadata.style, not as words that the model may read aloud.

3 / SAVE VALID AUDIO

WAV vs PCM

The default complete-request response is WAV with a RIFF header. Save the bytes directly; do not add a second WAV wrapper. Streaming instead uses raw PCM by default.

4 / STREAM IF NEEDED

Chunked PCM

The Gemini TTS streaming mode returns 16-bit, 24-kHz mono PCM chunks by default. Confirm chunk ordering, player format and buffering for your application.

VOICE CONTROL & MULTILINGUAL OUTPUT

Supported voices, languages, pronunciation and multi-speaker TTS.

Google reports 101 languages for Flash-Lite, with automatic input-language detection. Its wider 3.8 Flash TTS model reports 130. Language counts reflect provider support; they do not mean identical pronunciation or naturalness across every locale, voice or named entity. Build a listening test with your own words, dates, addresses and customer vocabulary.

Prebuilt voices can be selected in the TTS request, and Google also documents an Extended Voice Library, voice design and voice replication. For voice identity, use the voice field and/or supported designed-voice ID. A one-line text prompt is not a secure substitute for explicit voice authorization.

Single- and two-speaker support: Google documents speaker metadata for dialogue and up to two prebuilt-voice speakers per request. Each turn must supply speech_metadata.speaker matching a configured speaker. For scripts with more characters or voice-designed personas, synthesize turns separately where necessary and handle editing, alignment and transitions.

Event tags: insert momentary cues such as <short pause>, <laugh> or <sigh> at the specific event. Keep continuous style instructions separate in speech_metadata.style. Input text is treated as a transcript: old prompting like “Speaker 1:” or “Say cheerfully:” may be read aloud if inserted as plain speech.

Voice replication should only be used with appropriate consent and licensing, particularly for public-facing or commercial narration. Google's TTS guide describes voices, sample rates, supported formats and the relevant request format.

PRODUCTION AND MIGRATION CHECKLIST

Production considerations for low-latency and bulk audio systems.

01

Account for real audio seconds

Pricing is derived from generated audio tokens, not from transcript word counts. At 25 audio tokens/second, a 60-second file uses roughly 1,500 audio output tokens. Add separate text-input cost.

02

Batch where execution permits

For libraries and non-interactive narration, investigate Batch or Flex prices and capacity. For latency-critical voice-agent pipelines, benchmark your chosen serving tier end to end.

03

Segment long transcripts

The input limit is 8,192 tokens and the output serving limit is 16,384. Split longer scripts at natural sentence or scene boundaries; maintain consistent voices and review audible joins.

04

Upgrade from 3.1 carefully

Flash-Lite is Google's suggested replacement for gemini-3.1-flash-tts-preview. Migrate old role/style text into structured speech metadata, and update WAV handling rather than only replacing the model ID.

05

Use appropriate output formats

Google supports WAV, raw PCM, μ-law and A-law choices. Confirm the integration needs (browser playback, telecom gateway, streaming) and sample-rate requirements before storing files.

06

Plan fallbacks and permissions

Apply quotas, errors, retry budgets and privacy policies. Always keep API keys secret and confirm rights to produce any replicated voice. Voice synthesis does not replace an agent's reasoning, speech recognition or Live conversation session.

TECHNICAL LIMITATIONS

What Flash-Lite TTS does not do.

Google's model card lists audio generation as supported, but not general-purpose function calling, code execution, search grounding, structured text output, image generation, thinking or Live API for this model. It is a speech generation endpoint: connect separate models or tools when you need a fully conversational voice agent, retrieval or planning.

The model card also lists caching as unsupported despite the cached-input line on the pricing page. Both pages are linked above. For trustworthy estimates and production decisions, use verified billed usage and do not assume every listed billing dimension can currently be enabled for this TTS SKU.

The serving limits are not a promise of an arbitrary uninterrupted audiobook in one request. For substantial narration, split into multiple manageable inputs and test silence, pronunciation, continuity and voice consistency between outputs.
