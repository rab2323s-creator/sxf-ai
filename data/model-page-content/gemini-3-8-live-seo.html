What is Gemini 3.8 Live?

Gemini 3.8 Live is Google's real-time native-audio model for two-way spoken conversations, voice agents and visual assistance. Use the Gemini Live API with the exact model ID gemini-3.8-live to stream speech, accept text and visual inputs and call tools while a conversation continues. It is optimized for responsiveness, not for lengthy background planning.

The developer API model card documents 131,072 input tokens and 65,536 output tokens. Paid rates begin at $0.75/1M text input tokens and $4.50/1M text output tokens, but a spoken session uses separately billed audio. Google lists approximate audio equivalents of $0.005 per input minute and $0.018 per generated minute. Those minute figures are reference estimates, not a universal per-call price.

MODALITIES

Speech + text + vision

Accepts text, image, audio and video input; delivers streamed native audio and optional transcripts/text. This is not an image-generation model.

TOOL CALLING

Non-blocking by default

Async function calls can run while speech continues. Blocking mode is available when explicitly declared; protect writes and side effects with server-side authorization.

TURN-TAKING

Barge-in and streaming

Native audio and live input let users interrupt and correct a request. Measure actual first-audio latency and accidental interruptions on your own hardware.

REASONING CONFIG

No thinking_level parameter

Google describes interleaved reasoning but explicitly says not to send thinking_config or thinking_level for standard 3.8 Live.

IMPLEMENTATION / PYTHON

How to use Gemini 3.8 Live API: WebSocket and Google GenAI SDK.

The simplest supported developer workflow is a server-to-server session through the official google-genai Python package. Install it with pip install -U google-genai, provision a Gemini API key as an environment variable and choose the exact model string. The example below sends text and reads native audio chunks; it is a minimal integration illustration, not a deployed phone-service implementation.

import asyncio
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

async def main():
    async with client.aio.live.connect(
        model="gemini-3.8-live",
        config={"response_modalities": ["AUDIO"]},
    ) as session:
        await session.send_realtime_input(
            text="Give me a short spoken greeting for a visitor."
        )
        audio_chunks = []
        async for message in session.receive():
            content = message.server_content
            if content and content.model_turn:
                for part in content.model_turn.parts:
                    if part.inline_data and part.inline_data.data:
                        audio_chunks.append(part.inline_data.data)
            if content and content.turn_complete:
                break
        print("Received", len(audio_chunks), "audio chunks")
        # Decode/play as 24 kHz PCM in a real application.

asyncio.run(main())

For microphone input, send raw 16-bit little-endian PCM chunks using session.send_realtime_input(audio=...) and a MIME type such as audio/pcm;rate=16000; output is 24 kHz PCM. A real client needs microphone capture, playback buffering, cancellation, tool response handling and robust reconnect logic. See Google's Live API SDK walkthrough.

Security: keep production API keys on a backend. For direct browser-to-Google connections, use short-lived ephemeral tokens; never embed a permanent credential in frontend HTML or JavaScript.

MIGRATION AND VOICE OPERATIONS

Gemini 3.8 Live migration, async tools, interruptions and session limits.

  1. Change the model ID: move from gemini-3.1-flash-live-preview to gemini-3.8-live, and confirm the account and API path support the new endpoint.
  2. Remove unsupported reasoning settings: omit thinking_config and thinking_level. Those controls belong to other models, including Extended Thinking.
  3. Declare tool behavior deliberately: NON_BLOCKING is the default; BLOCKING can be set for sequential calls. For payments, bookings or record edits, enforce authorization, deduplication and human confirmation in the application.
  4. Handle interruption: automatic voice activity detection and client speech can interrupt model output. Track partial audio and never mark an interrupted tool action successful merely because a phrase was spoken.
  5. Manage session state: plan for connection termination and resumption; tune context compression for longer conversations. A large token context is not a guarantee of uninterrupted live connections.
  6. Inspect both forms of output: streamed audio chunks and transcription events can differ. Monitor spoken output completion, silence, dropped connections and retry behavior in real calls.

Google's session-management guide describes connection lifetime, resumption and compression. These are infrastructure concerns separate from the 131K-token model limit. Default turn coverage may include live video frames; send visual input only when it improves task quality and justifies cost.

COMMON DEVELOPER QUESTIONS

Gemini 3.8 Live FAQ: API, pricing and voice agents.

What is the Gemini 3.8 Live API model ID?

The exact stable Gemini Developer API model identifier is gemini-3.8-live. It connects through the Gemini Live API rather than a plain text-generation-only workflow.

Is Gemini 3.8 Live free?

Google lists a free tier with applicable limits. Paid Standard rates differ across text, audio and image/video modalities. Check current eligibility and quotas in Google AI Studio.

How much does a Gemini 3.8 Live voice session cost?

Google's audio equivalents are approximately $0.005 per input minute and $0.018 per output minute. Five input minutes and three output minutes therefore total about $0.079 for audio alone, before other usage and service costs.

Can Gemini 3.8 Live call tools without interrupting speech?

Yes. Non-blocking asynchronous function calls are supported and are the default mode. Apps still need robust tool authorization, result matching and error handling.

Can I set thinking_level on Gemini 3.8 Live?

No. Google's model migration guide says thinking_level and thinking_config are unsupported in standard 3.8 Live; use Extended Thinking when configurable reasoning is required.

Is Gemini 3.8 Live the same as Gemini 3.8 Flash TTS?

No. Live is for conversational streaming speech with real-time input and tool calls; Flash TTS is for producing expressive audio from text.
