DIRECT SEARCH ANSWER · USD PER MILLION TEXT TOKENS

GPT-6 Sol API pricing: input, cached tokens, cache writes and output.

For a Standard API request with 272,000 or fewer input tokens, original GPT-6 Sol costs $2 input, $0.20 cached reads, $2.50 cache writes and $10 generated output per million tokens. Above 272,000 input tokens, input and cache rates double and the output rate increases by 50% for the whole request. The number of input tokens includes uncached input, cached reads and cache writes in the SXF cost scenarios.

Transparent methodology and limitations

Input tokens = new input + cache reads + cache writes. For each category, multiply the number of tokens by the matching published USD-per-million rate and divide by 1,000,000. If input tokens are strictly greater than 272,000, multiply all input/cache rates by 2 and the output rate by 1.5. The same formula is applied to both model IDs, with each model's own rates.

The CSV records all counts, calculated costs and the pricing tier used. The site-build test independently recalculates the study from the repository's versioned provider catalog and rejects pricing drift. Outcomes here show potential list-rate cost differences only. Real economics include response length, cache hits/misses, retries, tool calls, quality validation, regional processing, latency and processing mode. There is no measured success-rate or latency advantage claimed.

MODEL NAMING & MIGRATION · IMPORTANT FOR SEARCHERS

GPT-6 Sol vs GPT-6.1 Sol: which model is newer, cheaper and compatible?

GPT-6 Sol is the original September 22, 2026 model (gpt-6-sol). GPT-6.1 Sol arrived September 29, 2026 (gpt-6.1-sol) as the newer Sol offering. They are distinct API endpoints, with different knowledge cutoffs, cached-input prices and supported reasoning/tool configurations. A keyword like “gpt sol” is ambiguous: this page deliberately identifies both IDs rather than treating them as interchangeable.

COPYABLE DEVELOPER START · NO PRIVATE KEYS ON THE PAGE

How to call GPT-6 Sol using the OpenAI Responses API.

Use the exact original model ID gpt-6-sol and choose an available reasoning effort. Example below uses a short text prompt; adapt it for testing with real unit tests and human review. The SDK reads OPENAI_API_KEY from the environment. This snippet is illustrative and was not executed against a paid API as part of the SXF pricing study.

from openai import OpenAI

client = OpenAI()  # reads OPENAI_API_KEY
result = client.responses.create(
    model="gpt-6-sol",
    reasoning={"effort": "medium"},
    input="Review this code change. List risks and specific regression tests."
)
print(result.output_text)

How should production teams evaluate it?

  1. Build a representative held-out set of tasks with explicit acceptance criteria and hard failure cases.
  2. Record prompt, model ID, reasoning effort, tool configuration, version and output for each run.
  3. Measure task success, human corrections, end-to-end latency, actual input/cache/output usage and retry frequency.
  4. Run the same workload on GPT-6.1 Sol and Astra. Compare cost per validated result; keep provider launch benchmarks separate from your measurements.

For tool calling, prefer the Responses API per OpenAI's original Sol model card. For prompts with reusable prefixes, follow the current prompt-caching guidelines. Do not expose API keys in client-side code or GitHub commits.
