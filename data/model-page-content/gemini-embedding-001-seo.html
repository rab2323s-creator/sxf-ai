What is Gemini Embedding 001?

Gemini Embedding 001 (gemini-embedding-001) is Google's stable text embedding model. It converts text into numerical vectors to help software find related passages by meaning instead of exact keywords. It is designed for semantic search, retrieval-augmented generation (RAG), clustering, classification and similarity scoring—not writing chat responses.

Google documents 2,048 input tokens per text and a 3,072-dimensional default vector, with shorter vectors such as 768 and 1,536 dimensions available to trade storage against retrieval quality. The Gemini Developer API charges $0.15 per million input tokens for paid Standard use and $0.075 per million for paid Batch use; an eligible free tier is also listed.

As of October 14, 2026, this text-only model remains available. Gemini Embedding 2 is Google's newer multimodal offering. Its vectors are not interchangeable with Embedding 001 vectors, so an upgrade requires re-embedding stored documents and queries. Google's embeddings documentation explains the migration rules.

Gemini Embedding 001 pricing: free tier, Standard and Batch.

Google bills this embedding model on input text tokens, not output tokens. A vector is returned instead of generated prose, so a separate text-generation output rate does not apply. Paid Standard pricing is $0.15 per 1 million input tokens; the asynchronous Batch API is $0.075 per 1 million, a 50% reduction for workloads that can tolerate delayed processing. VECTOR SPECIFICATIONS

2,048-token input limit, 3,072 dimensions and smaller embeddings.

The 2,048-token maximum applies to the input text sent to gemini-embedding-001. It is not a 2K-token generative context window: this endpoint generates a vector, not a chat completion. For long documents, chunk by tokens and add source metadata before indexing. Avoid silently truncating policies, citations or headings that matter to retrieval quality.

By default, Google returns a 3,072-number vector. Its Matryoshka Representation Learning support lets developers request shorter vectors using output_dimensionality. Google's suggested options are 768, 1,536 and 3,072 dimensions. Smaller vectors can materially reduce vector-database size and similarity-search compute, but the best dimensionality depends on your own retrieval recall and language mix.

Important: manually normalize shortened Embedding 001 vectors

Google notes that truncated Embedding 001 vectors should be normalized before cosine or dot-product ranking; the full 3,072-dimensional vector is already normalized. This differs from Gemini Embedding 2, which automatically normalizes shortened output. Whatever dimensionality you choose, configure your vector index to the same fixed dimension as both stored vectors and query vectors. Do not mix dimensions in one index. See Google's normalization guidance.

RETRIEVAL QUALITY

Which Gemini Embedding 001 task_type should you use?

Unlike the newer Embedding 2 API, Embedding 001 uses the task_type parameter to optimize different relationships between text vectors. For document search, embed your indexed passages with RETRIEVAL_DOCUMENT and the search prompt with RETRIEVAL_QUERY. Matching the task to the workflow is often more useful than blindly increasing vector dimensionality.

DEVELOPER EXAMPLES

Gemini Embedding 001 Python API: generate a 768-dimensional vector.

Install Google's supported SDK with pip install -U google-genai. Set GEMINI_API_KEY in your environment; never paste your key into a browser-side page. This minimal Python example embeds a document using the Gemini API and explicitly requests 768 dimensions:

from google import genai
from google.genai import types

client = genai.Client()
response = client.models.embed_content(
    model="gemini-embedding-001",
    contents="Refunds are available within 30 days with a receipt.",
    config=types.EmbedContentConfig(
        task_type="RETRIEVAL_DOCUMENT",
        output_dimensionality=768,
    ),
)
document_vector = response.embeddings[0].values
print(len(document_vector))  # 768

The response contains embedding vectors, not a summary or generated answer. For search indexes, you should store each vector alongside a document identifier, title, chunk number, update timestamp and access-control metadata.

Python example: query-document retrieval with cosine similarity

Use RETRIEVAL_DOCUMENT for indexed passages, RETRIEVAL_QUERY for the user question, and normalize both 768-dimensional vectors before comparing them. The following demo deliberately uses small in-memory vectors so it can be understood without an external vector database:

import math
from google import genai
from google.genai import types

client = genai.Client()
documents = [
    "A customer may request a refund within thirty days.",
    "Shipping usually takes three to five business days.",
]
doc_vectors = client.models.embed_content(
    model="gemini-embedding-001",
    contents=documents,
    config=types.EmbedContentConfig(
        task_type="RETRIEVAL_DOCUMENT",
        output_dimensionality=768,
    ),
).embeddings

query_vector = client.models.embed_content(
    model="gemini-embedding-001",
    contents="How long do I have to ask for a refund?",
    config=types.EmbedContentConfig(
        task_type="RETRIEVAL_QUERY",
        output_dimensionality=768,
    ),
).embeddings[0].values

def unit(vector):
    length = math.sqrt(sum(value * value for value in vector))
    return [value / length for value in vector] if length else vector

q = unit(query_vector)
scores = [
    sum(a * b for a, b in zip(q, unit(item.values)))
    for item in doc_vectors
]
best_index = max(range(len(scores)), key=scores.__getitem__)
print(documents[best_index], scores[best_index])

These scores demonstrate a vector-retrieval technique; they do not prove a fixed accuracy. In production, compute embeddings offline, keep access controls in the retrieval layer, apply metadata filters and optionally rerank the top candidates before sending grounded passages to a generative answer model. See Google's Python and task-type examples.

REAL APPLICATIONS

How to use Gemini Embedding 001 for semantic search, RAG and recommendations.

SEARCH

Semantic document search

Index support articles or product descriptions as passage vectors; retrieve relevant chunks when users ask in different wording. Preserve citations and permissions with each result.

RAG

Grounded question answering

Retrieve passages using embeddings, then give those passages to a separate generative model. Gemini Embedding 001 itself does not formulate the final prose answer.

PRODUCTS

Recommendations and deduplication

Find descriptions that convey similar intent, cluster duplicate records or build related-product suggestions. Test on genuine catalog examples.

ANALYTICS

Clustering and classification

Group tickets or feedback into topics and train downstream classifiers. Evaluate language coverage and class balance rather than treating vector proximity as certainty.

A dependable RAG indexing pipeline

  1. Prepare and clean: parse documents, keep titles, permissions and source links.
  2. Chunk by tokens: keep each text input at or under 2,048 tokens; test overlaps and section boundaries for your data.
  3. Embed documents: use RETRIEVAL_DOCUMENT and one consistent dimensionality.
  4. Search: embed questions with RETRIEVAL_QUERY, filter by user permissions, then rank the candidate chunks.
  5. Answer with citations: pass trusted retrieved passages to a separate Gemini chat model and evaluate groundedness and refusal behavior.

For privacy-sensitive data, send only documents you are authorized to process; review Google's free-tier versus paid-tier data-use terms. Embedding is a search primitive, not a substitute for an access-control system or factual verification.

2026 MODEL COMPARISON

Gemini Embedding 001 vs Gemini Embedding 2: which should you use?

Google released Gemini Embedding 2 as a newer multimodal embedding model. Embedding 001 remains relevant for existing text-only indexes and its lower published text-token rate. Embedding 2 is more flexible if you need vector search across text, images, audio, video or PDFs. The two models operate in incompatible embedding spaces—rebuild the index rather than mixing generations.

Migration checklist from Embedding 001 to Embedding 2

Re-embed your stored corpus and all search queries using the new model; choose a consistent dimension; create a separate vector index; retune similarity thresholds; compare offline recall, ranking, speed and actual costs; and switch traffic gradually with a fallback. Never compare an Embedding 001 vector directly with an Embedding 2 vector, even when both have 768 dimensions. Consult Google's official migration section.

For a broader provider comparison, see Cohere Embed v4.0, Codestral Embed and Google's model catalog. Benchmark any replacement using the same dataset, retrieval task and infrastructure rather than comparing prices alone.

FREQUENTLY ASKED QUESTIONS

Gemini Embedding 001 FAQ.

What is Gemini Embedding 001 used for?

Gemini Embedding 001 converts text into numerical vectors for semantic search, RAG document retrieval, clustering, classification and similarity. It does not generate conversational text.

How much does Gemini Embedding 001 cost?

Google lists $0.15 per million input text tokens on the paid Standard Gemini API tier and $0.075 per million on Batch. An eligible free tier also exists. These are embedding input charges, not generative output-token charges.

Is Gemini Embedding 001 free?

Google lists a free Gemini API tier for this model, subject to limits and data-use terms. Production paid usage is charged by input tokens. Check the official pricing page for your account and serving route.

What is the maximum Gemini Embedding 001 input size?

Google documents a limit of 2,048 input tokens per text. Chunk longer documents before embedding them and preserve metadata to reconnect retrieved results with the source.

How many dimensions does Gemini Embedding 001 return?

The default embedding vector has 3,072 dimensions. Google recommends evaluating 768, 1,536 or 3,072 dimensions depending on the desired storage and retrieval-quality trade-off.

Does Gemini Embedding 001 support images or video?

No. Gemini Embedding 001 is text-only. Google's newer Gemini Embedding 2 supports embedding text, images, video, audio and PDFs in a unified multimodal vector space.

How do I use Gemini Embedding 001 in Python?

Install the google-genai SDK, provide GEMINI_API_KEY, then call client.models.embed_content with model gemini-embedding-001 and an optional EmbedContentConfig specifying task_type and output_dimensionality.

Which task types should I use for RAG search?

Use RETRIEVAL_DOCUMENT when indexing source passages and RETRIEVAL_QUERY for the user's search text. Embed both sides with the same model and dimensionality and evaluate ranking quality.

Do I need to normalize 768-dimensional Gemini Embedding 001 vectors?

Yes. Google recommends manual normalization for Embedding 001 vectors truncated below the default 3,072 dimensions before cosine or dot-product comparisons. Gemini Embedding 2 automatically normalizes shortened vectors.

Can I mix Gemini Embedding 001 and Gemini Embedding 2 vectors?

No. Google states their embedding spaces are incompatible. Migrating requires re-embedding the stored corpus and query vectors and validating a separate index.

What is the difference between embedding and text-generation models?

An embedding model returns a fixed-length vector representing text meaning, useful for search and similarity. A generative Gemini model produces text or other content; RAG commonly combines vector retrieval with a separate generator.
