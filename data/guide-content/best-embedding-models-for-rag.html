Embedding dimensions, storage and retrieval quality

A 3,072-dimensional float32 vector stores 3,072 numbers, or 12,288 raw bytes before index structures, IDs, metadata, replicas and compression. Reducing the dimension to 768 cuts raw vector storage by 75%, but can change ranking quality. Use a retrieval validation set to decide whether that trade-off is acceptable.

Cohere Embed 5 offers dimension controls; do not assume different providers use the same preprocessing or similarity normalization.

Gemini Embedding 001 vs Gemini Embedding 2

Gemini Embedding 001 is Google's established text-only embedding model, suitable for semantic search over articles, customer tickets and text chunks. Its documented input limit is 2,048 tokens. Use different task types such as RETRIEVAL_DOCUMENT for indexed passages and RETRIEVAL_QUERY for search queries. Its current published Standard input price is $0.15 per million text tokens.

Gemini Embedding 2 handles images, audio, video and PDFs as well as text in a unified multimodal embedding space. For text it offers an 8,192-token input limit, with output dimensions configurable between 128 and 3,072. Its Standard rate for text is $0.20 per million tokens; image, audio and video prices use different meters and must not be compared as if they were pure text tokens.

The API task instructions also differ: Embedding 001 has a task-type parameter, while Embedding 2 uses natural-language instructions in the prompt instead of the same task-type control. Most importantly, **the vector spaces are not compatible**. To migrate, re-embed both your documents and queries; do not mix both generations in one nearest-neighbor index even if their vectors happen to share the same dimensionality. Google's official embeddings documentation covers these differences.

Choose Embedding 001 when your existing text-only index performs adequately and operational stability outweighs the newest modalities. Evaluate Embedding 2 for multimodal documents, longer text chunks or new greenfield deployments. Google's live model lifecycle documentation should inform any long-term maintenance plan.

Cohere Embed 5 Pro vs Embed 5 Fast

Cohere separates its fifth-generation Embed family into Pro and Fast. Pro is positioned for retrieval quality in demanding enterprise workflows and Fast for low latency and throughput. Both support multilingual/multimodal retrieval use cases. They share an Embed 5 vector space, so it can be reasonable to compare a Pro-based document index with a Fast-based query path—subject to the vendor's supported settings and a production evaluation.

This shared-space capability is an architectural advantage, not a claim of identical accuracy. You should still benchmark the Pro–Pro, Fast–Fast and Pro–Fast combinations with the same index, language mix and query distributions. Check whether query-time and document-time endpoints impose different input formats, rate limits, and latency expectations.

Cohere Embed v4.0 remains an earlier-generation multimodal alternative. Do not assume Embed v4.0 vectors can be mixed into an Embed 5 index. Cohere's model-provider guide also explains the distinction between Embeddings and Rerank 4.

Switching embedding models without breaking search

A vector index encodes learned geometry. Even with the same number of dimensions, two differently trained models can map identical text to unrelated coordinates. A migration is therefore a data engineering project, not a simple change to a model ID.

  1. Version every vector. Store embedding model, dimensionality, input normalization, document checksum and indexing timestamp.
  2. Create a parallel index. Re-embed the representative corpus with the candidate model. Do not overwrite your current production vectors.
  3. Run duplicate queries. Generate query vectors with the matching model and route to the matching candidate index.
  4. Measure retrieval. Compare Recall@5/10, MRR, nDCG@10, multilingual slice performance and answer faithfulness.
  5. Inspect failure cases. Pay attention to OCR-heavy passages, code, tables, negation, long documents and permissions-based filters.
  6. Roll out gradually. A/B test latency, operating cost and retrieval relevance; keep rollback until the new index is complete.

How to build a production RAG pipeline with these embeddings

For document-heavy workflows, parse PDFs into structured paragraphs or tables, clean duplicated boilerplate, and preserve page numbers and access-control lists. Tokenize or estimate chunk sizes using the endpoint's tokenizer or documented token-counting route; character counts alone are unreliable. Use stable chunk IDs and include metadata such as tenant, title, source, section and revision.

Build a hybrid index combining lexical terms with vector similarity if users search for IDs, filenames or exact legal clauses. Add metadata filters before returning results, rather than relying on the answer generator to hide unauthorized text. A reranker such as Cohere Rerank 4 Pro can reorder the top candidates; compare this against a no-rerank baseline because the latency and billing can outweigh marginal gains on small collections.

Finally, pass the selected source chunks to a generative model and require citations to source document IDs. Measure answers for unsupported statements as well as relevance; a vector match is only a retrieval signal, not a truth certificate.

Python API examples: Gemini and Cohere embeddings

Google Gemini Embedding 001

Use the supported google-genai SDK and an environment-provided GEMINI_API_KEY. For an index of 768-dimensional vectors, the same model and dimension must be used for the query side.

from google import genai
from google.genai import types

client = genai.Client()
result = client.models.embed_content(
    model="gemini-embedding-001",
    contents="Refunds can be requested within 30 days.",
    config=types.EmbedContentConfig(
        task_type="RETRIEVAL_DOCUMENT",
        output_dimensionality=768,
    ),
)
vector = result.embeddings[0].values
print(len(vector))  # 768

For Embedding 001, manually normalize reduced-dimensional vectors before cosine or dot-product search. Google documents different multimodal request handling and normalization behavior for Embedding 2; follow its current migration and SDK examples rather than reusing task-type arguments without checking.

Cohere Embed 5 Fast

Install cohere, set CO_API_KEY and use the SDK's documented v2 embedding shape. Cohere's Embed 5 interface accepts content blocks rather than a universally interchangeable raw text API for every version.

import os
import cohere

co = cohere.ClientV2(api_key=os.environ["CO_API_KEY"])
response = co.embed(
    model="embed-v5.0-fast",
    input_type="search_document",
    embedding_types=["float"],
    inputs=[{"content": [
        {"type": "text", "text": "Refund requests close after 30 days."}
    ]}],
)
print(response)  # Inspect vectors and usage fields

Use Cohere's Embed model guide and API reference for model availability and exact input/response shapes. Never expose either provider's secret API key in a public web page.

Evaluation: how to decide which embedding model is actually best

Vendor benchmark charts are useful for shortlisting but cannot establish which model wins your own retrieval workflow. A defensible RAG evaluation begins with real queries and an independently labeled set of relevant document IDs. For instance, use 300–1,000 queries sampled across popular topics, long-tail searches, multiple languages, out-of-scope questions and known failure cases; the exact sample size should be justified by your error tolerance.

Separately test what changes when reranking or query expansion is added. Record uncertainty and never promote a provider-reported benchmark as your own independent result.

Embedding models for RAG: frequently asked questions

What is the best embedding model for RAG?

There is no universal best model. Evaluate retrieval quality, supported input types, cost, vector dimensions, language support, latency and embedding-space compatibility on a labeled corpus. Gemini Embedding 001, Gemini Embedding 2, Cohere Embed 5 Pro and Fast are practical candidates for different requirements.

Is Gemini Embedding 2 better than Gemini Embedding 001?

Embedding 2 supports more input modalities and longer text inputs. Whether it improves your retrieval ranking depends on the actual corpus. Its vectors cannot be mixed directly with Embedding 001 vectors.

How much do Gemini embeddings cost?

For paid Standard text inputs, Gemini Embedding 001 is listed at $0.15 per million tokens and Embedding 2 at $0.20. Their Batch text rates are $0.075 and $0.10. Non-text modalities and downstream RAG costs are separate.

Can I mix Cohere Embed 5 Pro and Fast vectors?

Cohere documents a shared embedding space for Embed 5 Pro and Fast, enabling supported mixed use. Verify consistent dimensions and evaluate retrieval quality. Do not extend this assumption to older Embed versions or other providers.

Can Gemini and Cohere embedding vectors share one index?

No. Separate model families have independent learned coordinate systems. Store and search vectors generated by the matching model and dimensionality. A migration normally requires re-embedding both documents and queries.

Do I need a reranker with embeddings?

Not always. A reranker can improve relevance after initial vector or hybrid retrieval, but it increases cost and latency. Compare Recall@K and downstream grounded-answer quality with and without the reranker.

What vector dimensions should I use?

Test 768, 1,536, 2,048 or 3,072 where each model supports them. Smaller vectors reduce raw float32 storage, but the retrieval-quality trade-off depends on data and model. Keep document and query dimensions identical.

What does it cost to embed one million documents?

It depends on total text tokens, not document count. If each document averages 500 tokens, 1 million documents mean about 500 million input tokens. At Gemini Embedding 001 Standard text pricing, the illustration is $75 before index storage and retrieval costs.
