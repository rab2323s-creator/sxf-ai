DIRECT ANSWER

What is Claude Sonnet in GitHub Copilot?

Claude Sonnet in GitHub Copilot means Anthropic's Claude Sonnet model is available as a model choice inside GitHub's Copilot experiences. Claude is the model family; Sonnet is a model tier; GitHub Copilot is the product and execution environment that supplies editor integration, context, tools, governance and billing. Choosing Sonnet changes the reasoning model available to the Copilot workflow. It does not turn Copilot into Anthropic's Claude Code product or automatically confer unrestricted access to the terminal, repository or external services.

As of October 10, 2026, Claude Sonnet 5.5 is generally available in GitHub Copilot following GitHub's September 28 announcement. GitHub lists support in VS Code, GitHub.com and Copilot CLI for eligible users, subject to product and organizational settings. Anthropic's standalone API pricing and Claude.ai subscriptions should not be confused with Copilot's billing and entitlements. [1][2][10]

STEP-BY-STEP

How to enable Claude Sonnet in GitHub Copilot (VS Code, GitHub.com and CLI)

How do you select Sonnet in Visual Studio Code?

  1. Update VS Code and the GitHub Copilot extension, then sign in to the correct eligible GitHub account.
  2. Open Copilot Chat and start a new coding conversation or task.
  3. Locate the model picker in the chat interface. The exact placement changes across VS Code and Copilot extension releases.
  4. Select Claude Sonnet 5.5 when available. If the model is absent, check your subscription and organizational model policy before reinstalling anything.
  5. Try a bounded repository task and review the diff and tool outputs. Changing the model alone does not activate agent mode or automatic code edits.

How do you use Sonnet on GitHub.com?

Open a GitHub Copilot Chat surface that exposes model selection. Choose Sonnet 5.5 from the available models and ask a narrowly specified question or repository-related task. Features differ among chat, pull request review and cloud-agent contexts; do not assume the model selector is identical across all of them. [2][3]

How do you change to Sonnet in Copilot CLI?

Launch the official Copilot CLI, authenticate and use the CLI's documented model-selection control—commonly /model in interactive sessions—then select the supported Sonnet model. CLI options can change, so consult its current help and GitHub documentation rather than relying on a hard-coded, unverified command-line flag. In a repository, keep working-directory permissions and approval prompts constrained. [8]

No fake screenshots or universal click paths

Model-picker wording, default model and surface availability can shift by release. This guide describes durable selection steps and links to official interface documentation instead of presenting old UI screenshots as current fact.

COST EXPLAINED

How much does Claude Sonnet cost in GitHub Copilot? Plans, AI Credits and token billing

The central billing question in late 2026 is how Copilot measures the particular model's token usage and AI Credits, not the old shortcut “one prompt costs one fixed premium request.” Subscription fees, included credits, any additional purchased usage, cached tokens and output volume all influence the effective price. GitHub's published billing documentation and model-rate tables should be checked before a purchasing decision. [4][5][6]

Keep pricing claims falsifiable

Quoted per-million-token rates are rate-card reference values, not a promise that every Copilot request is billed identically. Effective cost can differ with caching, included credits, feature-specific usage and organization settings.

What would a Sonnet task cost before included credits?

Suppose a task uses 40,000 regular input tokens and 12,000 output tokens, with no prompt-cache discounts or extra charges. At the reference rates above, the modeled usage cost is $0.20: 0.04 × $2.00 + 0.012 × $10.00. That is an illustrative arithmetic example, not a measured Copilot invoice. A long iterative agent run may be much costlier because it replays context, reads repositories and performs multiple model calls.

What drives unexpectedly high Copilot model usage?

Large repository files, repeated terminal output, broad agent exploration, retries, high output-token counts, and poor cache reuse can dominate a task's cost. Teams should observe usage per accepted code change, not merely compare list prices per million input tokens. Set limits and review usage in Copilot's official billing views. [6]

MODEL CHOICE

Claude Sonnet vs Opus vs Haiku in Copilot: which model should you choose?

The right model depends on your task's complexity, latency budget, risk and verification needs. Sonnet is the practical starting point for broad everyday coding work; Opus can be worth considering for difficult reasoning-intensive work if its higher cost is justified; Haiku is attractive for bounded low-cost tasks. These are workflow-fit heuristics, not independent benchmark superiority claims.

Best uses for Claude Sonnet in Copilot: five coding tasks worth delegating

01

Repository investigation

Ask Sonnet to identify where a failure originates, quote file paths and explain its evidence before changing code.

02

Targeted bug fixing

Supply a reproducible failing case and ask for the smallest valid patch plus tests and residual risks.

03

Refactoring with constraints

Specify public interfaces and performance invariants, require a scoped diff and run the affected test suite.

04

Use Sonnet as a second reader to flag test gaps, security concerns, error paths and unwanted behavior changes; validate its findings.

05

Feature implementation

Provide acceptance criteria and allow bounded edits. Require a final summary of actual tool executions, changed files and unverified assumptions.

Separate chat suggestions from executed code changes. A model that writes a plausible patch in conversation has not necessarily modified a file, run a test or produced a trustworthy pull request. PRACTICAL INSTRUCTIONS

Four practical Claude Sonnet Copilot prompts that produce reviewable results

Good coding prompts specify environment, constraints, evidence, and the definition of done. These prompts can be adapted for your repository without requiring privileged autonomy.

BUG FIXInvestigate the failing authentication test. Locate the root cause, list the relevant files, propose the smallest change, then run only affected tests if tool access is approved. Report the exact commands executed and their exit status. Do not change unrelated files.
REFACTORRefactor this module without changing its public API. Before editing, identify invariants and current test coverage. After editing, explain the diff, execute available checks, and explicitly identify behavior you could not verify.
CODE REVIEWReview this pull request against the base branch. Prioritize correctness, security, race conditions and missing regression tests. Cite precise file and line evidence; distinguish confirmed issues from hypotheses. Do not modify code.
MIGRATIONCreate a dependency migration plan from the current lockfile. Identify breaking changes with official upstream references, enumerate required code edits, and propose verification gates. Do not update dependencies or access production systems before approval.

TROUBLESHOOTING

Why doesn't Claude Sonnet appear in GitHub Copilot? Eight checks

  1. Wrong account: verify you are logged into the GitHub account with the eligible Copilot subscription.
  2. Unsupported plan: check the eligible-plan list rather than assuming any free Copilot access includes Sonnet 5.5.
  3. Organization policy: Business and Enterprise administrators can limit which models are allowed.
  4. Different surface: VS Code, GitHub.com, code review, cloud agent and CLI may expose different model menus.
  5. Outdated editor or extension: update VS Code and the official Copilot extension, then reopen the chat picker.
  6. Gradual rollout or regional availability: check the supported-models documentation and current status rather than inferring a local installation defect.
  7. Model renamed or retired: look for exact release labels and migration notices; “Sonnet” by itself may refer to a different version.
  8. Usage or billing restrictions: review available AI Credits, spending controls and organization restrictions.

When escalating a missing-model issue, record your GitHub plan, organization policy state, VS Code/Copilot extension versions, product surface, date and what exact models appear. Do not publish private organization identifiers or credentials in a public issue.
