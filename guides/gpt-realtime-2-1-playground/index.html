THE SHORT ANSWER

How do you use the GPT-Realtime-2.1 Playground?

To try GPT-Realtime-2.1, open OpenAI’s official GPT-Realtime-2.1 model card, choose Try in Playground, sign in with an eligible API account, allow microphone access if requested and run a short, structured voice conversation. Check your account’s spending controls before using the API.

START HERE · DIRECT SEARCH INTENT

GPT-Realtime-2.1 Playground: exact setup steps

  1. Open the official entry point. Visit the GPT-Realtime-2.1 model page and use its “Try in Playground” action. We link to the documented entry point rather than guessing an undocumented deep link.
  2. Confirm access. Sign in to your OpenAI API account, check model availability, budget and limits. The model card does not list Free-tier API support.
  3. Choose the realtime voice experience. If the interface offers model selection, verify the exact model ID is gpt-realtime-2.1 rather than an older Realtime model or gpt-live-1.
  4. Grant microphone permission. Use headphones where possible to reduce echo; test in a quiet room before introducing background noise.
  5. Use one constrained instruction. Start with the SXF starter prompt below. Verify what the system says when information is missing instead of rewarding confident guesses.
  6. Run a 60–90 second task. Include a serial number, a correction, and one hypothetical booking action that must not happen without confirmation.
  7. Save evidence. Record scenario ID, model ID, prompt version, device, environment, output and any tool state. Export usage from your available telemetry rather than estimating tokens from call duration.

Playground controls and layout may change. The exact control labels after sign-in are account/interface dependent; the official model card is the source for the entry point.

COPY-READY · EXPERIMENT 01

First voice-agent test: a prompt that exposes real weaknesses

A good first test is not “Hello, how are you?” It should challenge entity recognition, clarification, interruption and authorization in the same short session. Use an invented customer and no production systems.

SXF starter instructions · editable test fixture
You are a careful voice assistant in a controlled evaluation.
Start with a short greeting. Ask one question at a time.
Before using any tool, restate the intended action and ask for confirmation.
Never claim a booking, refund, email, or database change happened unless a tool response confirms it.
If a name, date, code, or price is unclear, ask for clarification.
When interrupted, stop and respond to the user's latest correction.
Keep spoken answers concise, and explicitly state when you cannot verify a fact.

Read this test aloud

“I want to book a call next Thursday at 3 PM. My ticket is A–B–7–0–B. Actually, change that to Friday. Before you book anything, tell me what you heard.”

What success looks like: the agent asks for location/time zone when needed, captures the letters and digits rather than silently normalizing them, updates the day after correction and never claims a real booking occurred without an authorized tool confirmation.

This prompt is an original SXF test design, not a claim that we executed a paid session or measured model performance. Run it repeatedly before drawing conclusions.

IMPLEMENTATION · PRODUCTION ARCHITECTURE

How to connect GPT-Realtime-2.1 with WebRTC or WebSocket

The easiest Playground experiment requires no custom web app. Production architecture does. OpenAI’s current Realtime guidance uses a browser-facing WebRTC session with a short-lived client secret issued by your backend; server-managed audio can use WebSocket. Neither path requires putting your standard API key in public JavaScript.

WebRTC · browsers and mobile

Best when you need low-friction microphone capture, two-way audio and interruption handling in an interactive client. The Realtime server manages output-audio buffering on WebRTC connections.

Read official WebRTC setup ↗

WebSocket · server pipelines

Best when your server owns an audio stream, processing or integrations. Your client is responsible for playback state, stopping queued audio and truncating output after interruption.

Browser integration outline with the official Agents SDK

This is an integration outline based on the official Realtime API guide, not a copy-paste hosted service: the /api/realtime-token endpoint below is something you must implement on a trusted backend.

JavaScript · @openai/agents/realtime · client-side outline
import { RealtimeAgent, RealtimeSession } from "@openai/agents/realtime";

// Your backend returns a short-lived realtime client secret.
// NEVER expose a standard OpenAI API key in browser JavaScript.
const res = await fetch("/api/realtime-token", { credentials: "same-origin" });
if (!res.ok) throw new Error("Unable to obtain ephemeral session key");
const { client_secret } = await res.json();
if (!client_secret) throw new Error("Missing ephemeral session key");

const agent = new RealtimeAgent({
  name: "SXF Voice QA Assistant",
  instructions: "Ask for confirmation before tool side effects; do not invent results.",
});

const session = new RealtimeSession(agent, {
  model: "gpt-realtime-2.1",
});
await session.connect({ apiKey: client_secret });

// Implement /api/realtime-token on a trusted server.
// Create the secret with POST /v1/realtime/client_secrets.
// This sample is an integration outline, not a hosted SXF voice demo.

The backend should authenticate the caller, enforce rate limits and issue short-lived credentials using the documented POST /v1/realtime/client_secrets. Never place OPENAI_API_KEY in static site assets, a client-side environment file, or a Playground prompt. See the current Realtime getting-started reference for supported session shape and the latest SDK.

TURN TAKING · INTERRUPTION EVIDENCE

Server VAD vs semantic VAD: what changes when someone interrupts?

Realtime VAD (voice activity detection) marks the beginning and end of user speech. OpenAI documents two supported turn-detection strategies for applicable Realtime sessions: server_vad detects pauses, while semantic_vad considers whether the speaker appears to have finished their thought. Neither eliminates the need for device testing.

  • Short silence: If a user pauses mid-sentence, a strict silence threshold may terminate the turn before they finish. Test natural hesitations and long numbers.
  • Barge-in: Interrupt while the assistant is speaking, then correct an earlier instruction. The assistant must respect the new direction, not complete a stale action.
  • WebRTC/SIP behavior: OpenAI documents server-managed output buffering and automatic truncation of unplayed speech during user interruptions.
  • WebSocket behavior: Immediately halt local playback, discard queued audio and send conversation.item.truncate with the duration actually played. Otherwise the model may retain words the user never heard.

SXF analysis: interruption is a state-consistency problem, not only a response-speed metric. An agent can sound responsive yet issue an outdated tool call. Measure both the audible conversation and the authorized final state. Official VAD reference ↗

How to publish credible results later

  1. Freeze exact source audio, instructions, model ID, model settings, voice, transport and microphone chain.
  2. Run each scenario more than once and vary the seed audio across independent participants; repeated runs on one fixture are not an estimate of general performance.
  3. Log model usage, tool calls and event timestamps. Keep incorrect output rather than deleting failures.
  4. Score separately: semantic correctness, spoken identity accuracy, task acceptance, unauthorized effects, first-useful-audio time, interruption recovery and connection reliability.
  5. Publish sample size, errors, uncertainty and hardware limitations. Never present vendor launch claims as independent SXF results.

This aligns with the reliability framework in SXF’s twelve agent reliability metrics and the 25-test agent evaluation checklist.

GPT-Realtime-2.1 vs GPT-Realtime-2.1 Mini: which should you test first?

COMPLEX VOICE FLOWS

Start with GPT-Realtime-2.1

Use as a candidate when the workflow has difficult corrections, varied language, dense instructions, tool coordination or high cost of misunderstanding. This is a test starting point, not a proved performance ranking.

HIGH-VOLUME TRIAGE

Compare GPT-Realtime-2.1 Mini

Mini has lower public audio and text token rates and is positioned for faster, lower-cost voice interactions. Check alphanumeric capture and task acceptance before routing production traffic.

Decision rule: test both on the same seven scenario IDs, then compute cost per accepted task = total verified API + tool + operating cost ÷ accepted task count. If no accepted tasks were observed, the metric is undefined—not zero.

DIAGNOSTICS · PRACTICAL FIXES

GPT-Realtime-2.1 Playground not working? Seven checks

The model is missing from the Playground

Start at the exact model card, check model availability and API account tier, and confirm you did not select an older Realtime or unrelated GPT-Live model. Availability can vary by account.

Microphone access is blocked

Allow microphone permission in the browser and operating system. Use HTTPS or localhost in your own browser app and verify that another program is not holding exclusive mic access.

Audio echoes or the model hears itself

Use headphones, lower speaker gain and verify the browser’s input device. Repeat your test with the same mic and room to make comparisons meaningful.

The agent interrupts too soon

Revisit turn-detection settings; compare server VAD and semantic VAD with the same pause recording. Record the event boundaries instead of using only a subjective impression.

The agent ignores the latest correction

Inspect cancellation, playback queue handling and truncation. In WebSocket pipelines, stopping speaker output without synchronizing the conversation can retain unheard text.

A tool appears to run without confirmation

Do not rely on instructions alone. Require server-side authentication, explicit user approval, allowlisted tool actions and a verified success response before a spoken completion claim.

Billing exceeds the rough estimate

Use actual per-modality input, cached input and output token counts, plus additional tools and retries. Audio minutes are not a reliable substitute for token telemetry.

DIRECT QUESTIONS

GPT-Realtime-2.1 Playground FAQ

Where can I try GPT-Realtime-2.1 in a Playground?

Open the official GPT-Realtime-2.1 model page and select Try in Playground. Access and usage limits depend on your OpenAI API account.

Is the GPT-Realtime-2.1 Playground free?

Do not assume it is free. The model card lists Free-tier API access as unsupported; verify your account access and pricing before testing.

How much does GPT-Realtime-2.1 audio cost?

Official Standard API list pricing is $32 per million audio input tokens and $64 per million audio output tokens. Text and image input tokens have separate rates; token usage is not identical to minutes of speech.

What is the difference between GPT-Realtime-2.1 and GPT-Realtime-2.1 Mini?

Both support realtime voice workflows and tools. Mini has lower published modality-token rates; compare task acceptance, spoken accuracy and interruption behavior in your own repeated tests before choosing.

Should I use WebRTC or WebSocket for a voice agent?

Use WebRTC for interactive browser or mobile audio. WebSocket is useful for server-controlled audio pipelines. With WebSocket, your application must handle audio playback and truncation after interruptions.

Does GPT-Realtime-2.1 support video, fine-tuning or structured outputs?

No. The published model card lists video, fine-tuning and structured outputs as unsupported. It supports text input/output, audio input/output, image input and function calling.

How do I measure whether a voice agent actually works?

Test repeatable conversations against expected user intent, authorized tool calls, final application state, interruption handling, spoken accuracy and latency. A pleasant-sounding answer alone does not prove the action was completed.
