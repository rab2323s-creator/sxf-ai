SEARCH DEFINITION

What is open-weight LLM hosting?

Direct answer: Open-weight LLM hosting runs downloadable model parameters on external infrastructure and exposes an inference API. Depending on the product, the customer is billed per token, dedicated throughput or billable GPU time. Open-weight does not automatically mean every license qualifies as open source.

Choosing model weights, installing a runtime and running an internet-facing production service are different engineering tasks. An open-model catalogue helps pick models and licenses; local LLM deployment helps size a workstation; this guide answers the commercial question of where to operate an API at a measurable cost.

UNDERSTANDING THE BILL

Per-token LLM API pricing vs GPU hourly pricing: which is cheaper?

Direct answer: Neither billing model is universally cheaper. A token API charges for input and generated output; a GPU worker charges for billable compute time, potentially including warm-idle periods and extra resources. Normalize both to the same completed workload, latency and model quality.

Token cost = (input tokens × input price + output tokens × output price) / 1,000,000. GPU cost = billable worker hours × hourly GPU rate plus CPU, RAM, storage, network, replica and operations cost where applicable. A large monthly token count alone says little about GPU utilization or capacity.

SXF normalization rule

Calculate cost per 1,000 independently accepted responses with the same prompt distribution, rather than comparing $/million tokens against $/GPU-hour or dividing by raw HTTP 200 responses.

For very sporadic jobs, avoiding provisioned idle workers may favor a managed token API. For sustained demand, a custom serving engine may become attractive—but only if measured throughput satisfies the workload. Longer prompts, output-heavy tasks and concurrency change the break-even point.

Together AI vs Fireworks AI: which is cheaper for GPT-OSS 120B?

Direct answer: Both vendors publicly list $0.15 per million input tokens and $0.60 per million output tokens for gpt-oss-120b on the checked serverless tier. This is a price-list tie for one model, not an observed comparison of accuracy, time to first token or reliability.

The model IDs are openai/gpt-oss-120b on Together and accounts/fireworks/models/gpt-oss-120b on Fireworks. At 100,000 requests with 1,000 input and 250 output tokens each, the illustrative combined monthly list-price bill is $30.00 on either service, before volume contracts, cache effects and taxes.

At Fireworks the model card also distinguishes a much lower cached-input rate. Therefore workload caching can alter the comparison. HOURLY GPU ECONOMICS

Runpod vs Modal inference: which GPU hosting option costs less?

Direct answer: For the specific published examples checked, Runpod's H100 PRO Serverless worker costs $5.39 per GPU-hour, while Modal's H100 SXM5 rate is $0.001097 per GPU-second, or $3.9492 per hour. These are different GPU and product configurations, not a measured like-for-like inference benchmark.

At 120 billed GPU hours, the published GPU component is $646.80 on that Runpod Serverless tier versus $473.90 on Modal. Modal can bill CPU and memory separately; Runpod's Pods have separate price bands from its Serverless workers. Load times, autoscaling delays, minimum workers, storage, security requirements and available hardware must be included in an invoice-level comparison.

Modal also provides token-priced Shared Endpoints, so describing Modal exclusively as GPU-second billed is incorrect. Similarly, Together and Fireworks offer dedicated deployment products. The choice is between specific offerings, not arbitrary vendor labels. Sources: Runpod and Modal.

SXF BUYER DECISION PATH

Should you use a serverless LLM API or dedicated GPU hosting?

Direct answer: Start with quality and license requirements, then check whether you need custom weights. If not, two token APIs establish a useful baseline; if yes, benchmark a dedicated endpoint or controllable GPU worker under real target concurrency.

1. Can you use a listed model?

Choose a token API for a quick baseline when the model, context window and safety controls fit. Verify model ID, region and quotas.

2. Do you need your own checkpoint?

For quantized weights, a custom tokenizer or fine-tuned model, evaluate dedicated deployment or container-friendly GPU services.

3. Is traffic steady or bursty?

Count idle worker time and cold starts; compare demand by hour, not only monthly totals. Test capacity and latency at peak concurrency.

4. Does the response pass?

Keep schema validity, human acceptance, retries and cost of operational errors in the denominator of the final business decision.

If you also need multi-provider routing, fallback and cached responses, the SXF LLM Gateway guide covers that separate layer.

REAL WORLD PERFORMANCE

How should you compare LLM inference latency, throughput and cold starts?

Direct answer: Use one model, one prompt mix and recorded concurrency. Report p50/p95 latency, time to first token for streamed runs, output tokens per second, 429/5xx failures, billable worker time and answer quality. Do not turn vendor marketing metrics into independent test scores.

In production, a lower $/GPU-hour can lose to a faster or more highly utilized deployment. Prompt prefill, long context, tool-call format, reasoning configuration, streaming overhead and batch scheduling affect outcomes. Test at concurrency 1, 4 and 16 and publish medians plus tail latencies—never just a single favorable screenshot.

DIRECT SEARCH ANSWERS

Open-source LLM hosting: frequently asked questions

Direct answer: Choose a model and billable service tier first, then compare token economics, GPU-worker time and accepted-output quality. None of those units is interchangeable on its own.

What is the best open-source LLM hosting platform?

For ready-made managed model APIs, compare Together AI and Fireworks AI. For custom GPU/container control, evaluate Runpod and Modal. Match model availability, measured latency, traffic pattern, license and the full bill before choosing.

Is Together AI cheaper than Fireworks AI?

For the gpt-oss-120b public serverless model price checked on November 12, 2026, both list $0.15 per million input tokens and $0.60 per million output tokens. That is a list-price tie, not a measured performance tie.

How much does it cost to host gpt-oss-120b?

A hypothetical 100,000 monthly requests averaging 1,000 input and 250 output tokens cost $30 on the listed Together or Fireworks serverless rates before credits, caching and additional charges. GPU-hosted deployments require measured worker hours and additional resources.

Is Runpod cheaper than Modal for inference?

Not inherently. Runpod offers Pods and Serverless worker tiers; Modal charges GPU time and may charge CPU, memory and other resources. Their published H100 examples are different product configurations, so compare actual workload costs rather than bare hourly numbers.

What is the difference between token billing and GPU hourly billing?

With token billing, the provider charges for input and generated tokens. With GPU billing, you pay for billable worker compute time, potentially including idle periods or extra resources. Neither price describes cost per accepted answer without workload measurements.

When should I self-host an LLM rather than use a serverless API?

Self-host or use custom GPU deployment when you need custom weights, special inference controls, stricter runtime boundaries or sustained utilization. For unpredictable low volume, a per-token API often reduces idle-capacity exposure.

Can I use a custom Hugging Face model?

Custom weight support varies by provider and product. Check the exact model license, supported serving engine, hardware, region and deployment documentation. A serverless model API does not automatically accept arbitrary weight files.

How should I benchmark inference hosting platforms?

Pin the same model and prompt distribution, set identical output limits and concurrency, test cold and warm starts, and record p50/p95 latency, token usage, errors, actual cost and answer acceptance. Only compare TTFT if streaming is measured.
