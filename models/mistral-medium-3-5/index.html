01 / THE SXF ASSESSMENT

The model is capable. Its lifecycle is now the deciding factor.

Mistral Medium 3.5 is a frontier-class open-weight multimodal model positioned for coding and agentic tasks. It brings a documented 256K context window, structured-output and function-calling support, and transparent token-based API pricing. The important 2026 update is operational: Mistral's API model directory lists the model as deprecated as of 31 October 2026 and names Mistral Large 4 as the replacement for new integrations.

SXF DECISION BRIEF · NOVEMBER 2026

New API project? Evaluate Mistral Large 4 first, as the vendor directs. Existing Medium 3.5 production system? Do not assume an immediate shutdown; test a migration and confirm the contractual retirement date before changing traffic. Open-weight deployment? Treat model licensing, hosting costs and deployment requirements separately from hosted API pricing.

The Mistral legal-governance register still calls this model version Active with no retirement date listed. That record describes governance status; the API catalog explicitly flags Deprecated. SXF reports both instead of silently treating them as interchangeable.

03 / ENGINEERING CAPABILITIES

Capabilities that matter in real applications.

01 · Reliable structures

Structured outputs

Mistral's model card lists structured outputs. Use schema-constrained responses where supported, and still validate application-side JSON types, required fields and semantic correctness.

02 · System integration

Function calling & agents

The documented feature set includes function calling, agents and built-in tools. Measure tool-selection accuracy, argument validity, retry rate and permissions instead of counting tool calls as success.

03 · Working with evidence

Multimodal & Document QnA

Text/image input and provider-listed Document QnA make the model relevant to document-centric pipelines. Evaluate OCR quality, citation grounding and retrieval separately from reasoning.

04 · Throughput operations

Batching & predicted outputs

Both are listed in the provider's features. Check availability, latency and cost for the exact endpoints used in your environment; feature support does not guarantee identical behavior across deployment modes.

Where Medium 3.5 can still make sense

For a system already tuned to this version, retaining a pinned deployment while running a controlled migration can avoid regression. For long-context analysis, the 256K limit is a capacity figure, not evidence that recall or factual accuracy remains stable across the full window. For agents, monitor completion quality under realistic budgets and tool permissions.

What not to infer from a model card

  • Do not assume “open weights” means free managed API inference or unrestricted use.
  • Do not equate 256K context with 256K output tokens.
  • Do not assume support for a listed feature implies its availability on every endpoint, pricing tier or region.
  • Do not promote a benchmark score into a universal best-model claim without compatible measurement conditions.

06 / PRODUCT DECISION

Migrate deliberately: Medium 3.5 → Large 4.

The official Mistral model directory recommends Mistral Large 4 for new integrations. That is a lifecycle recommendation, not an SXF claim that Large 4 wins every task, runs cheaper or has identical contracts. A production migration should be treated as an engineering change with measurable acceptance criteria.

DEPRECATION IS NOT RETIREMENT

Mistral's lifecycle policy states that deprecated models remain accessible during the notice period; after retirement, requests to retired model identifiers may return HTTP 404. The governance register may still show the version as Active. Verify current API access and the retirement notice directly with Mistral before committing to a cutoff date.

  1. Inventory usage. Find all exact model IDs, aliases, fallbacks, prompts, tools and contractual dependencies. Avoid silent alias upgrades in controlled workloads.
  2. Build a representative evaluation set. Include real coding tasks, document workloads, long-context retrieval, edge cases, safety behavior and tool-call validity.
  3. Run an A/B evaluation. Hold the task, tool schema, evaluation harness and acceptance rubric constant. Record quality, p50/p95 latency, errors and cost per completed task.
  4. Check output contracts. Revalidate structured JSON, refusal behavior, long replies, tool parameters, context truncation and multimodal request formats.
  5. Roll out with safeguards. Start with a small traffic slice, set budget and quality thresholds, instrument regressions and keep a tested fallback.
  6. Document the decision. Record the source dates, chosen model identifier, benchmark build, billing assumptions and owner for future revalidation.

07 / DEVELOPER NOTES

Implementation checks for production systems.

Pin the model version explicitly and read the official lifecycle policy before you deploy. Mistral distinguishes stable version IDs from rolling aliases; aliases can change behavior or pricing. Since Medium 3.5 is deprecated, test a fresh authenticated request in your own account rather than assuming that historic model documentation proves availability.

Minimum observability checklist

  • Reliability: end-to-end task success rate, invalid structured outputs, failed tool calls and retry multiplier.
  • Performance: request latency distributions, input/output token counts and truncated or timed-out generations.
  • Quality: groundedness, source attribution, answer completeness and long-context recall on your own benchmark.
  • Security: prompt-injection testing, scoped tool permissions, private-data leakage and human review for high-stakes actions.
  • Economics: cost per successful outcome, cached-token eligibility, tokens consumed by tool loops and post-processing overhead.

08 / ANSWERS FIRST

Frequently asked questions.

Is Mistral Medium 3.5 deprecated?

Yes. Mistral's API model directory marks Mistral Medium 3.5 deprecated with a deprecation date of October 31, 2026, and recommends Mistral Large 4 for new integrations. Deprecated is not the same as retired.

What is the context window of Mistral Medium 3.5?

The official Mistral Medium 3.5 model card specifies 256k tokens. This is a context window, not a guaranteed maximum output length.

How much does Mistral Medium 3.5 cost?

The provider model card lists $1.50 per million input tokens and $7.50 per million output tokens. The SXF catalog also records $0.15 per million cached input tokens; verify current billing eligibility in Mistral Studio before relying on that tier.

Is Mistral Medium 3.5 open weight?

Mistral describes this release as open weights under a Modified MIT license. Open weights do not imply zero-cost hosted inference, unrestricted redistribution or that every deployment has identical behavior.

Can Mistral Medium 3.5 understand images and documents?

The model card presents a multimodal model and documents Document QnA as an available feature. Text and image inputs with text output are reported in the SXF model record; validate the actual API endpoint and format for your integration.

Should I migrate from Mistral Medium 3.5 to Mistral Large 4?

For new API integrations, Mistral recommends Large 4. Existing users should compare quality, token consumption, latency, price and safety on their own task set before switching.

How do I compare benchmark scores fairly?

Compare results only when the benchmark version, evaluator, test harness, tool settings and comparable group match. Do not combine scores from different tasks into a universal ranking.

Does deprecation mean the API is already unavailable?

No. Mistral's lifecycle policy says a deprecated model remains accessible during its notice period; after retirement, its identifiers can return HTTP 404. Check the current status and test your deployed model ID.
