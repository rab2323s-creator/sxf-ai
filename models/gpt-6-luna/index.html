What is GPT-6 Luna?

GPT-6 Luna is OpenAI's most cost-efficient GPT-6 tier, designed for focused, high-volume tasks. It is a reasoning-capable text model that accepts text and image inputs and produces text. With a 1,050,000-token context window, 128,000 maximum output tokens and a particularly low Standard API rate, Luna is a candidate for scaled extraction, classification, structured generation and controlled agent workflows.

It is not automatically the strongest GPT-6 model: GPT-6.1 Sol aims at complex coding, agentic and professional work, while GPT-6 Astra targets the hardest reasoning and high-stakes workflows. Luna can be the smarter economic choice when it passes your task's quality checks. The point of this reference is to show exactly what it can do, what it costs and where paying more may be justified.

Pricing detail most summaries miss: Luna's $0.10 input and $0.50 output prices apply to Standard requests with up to 272,000 input tokens. Above 272K input tokens, the entire request moves to higher rates—not just the part above the threshold.

LONG-CONTEXT ECONOMICS

What happens above 272,000 GPT-6 Luna input tokens?

OpenAI documents a strictly greater than 272,000 input-token boundary. At 272,000 input tokens or fewer, the shorter schedule applies. At 272,001 tokens and beyond, Standard pricing changes to 2× input, 2× cached input, 2× cache writes and 1.5× output across the whole request. This is a request-level tier switch, not an incremental overage fee.

EXAMPLE A · 272,000 INPUT$0.0282

Plus 2,000 generated output tokens. The request remains in the shorter Standard band.

EXAMPLE B · 272,001 INPUT$0.0559

Plus the same 2,000 output tokens. All billable categories now use long-context rates.

The sharp price step means applications hovering near 272K input tokens need careful context budgeting. Consider retrieval, document chunking, compaction and prompt deduplication when doing so preserves the information required for correctness. A larger window can process large inputs, but it does not guarantee perfect recall, and a small reduction in prompt length does not necessarily reduce task failure.

One million tokens of context is capacity—not the cheap-rate allowance. Luna can accept long text or image-grounded input within its 1,050,000-token context, but the extended schedule must be included in estimates for large documents, repositories and agent histories.

WHAT TO BUILD WITH LUNA

When should you choose GPT-6 Luna?

Choose from tasks that can be automatically checked, sampled by humans or escalated when confidence is low.

01 · STRUCTURED EXTRACTION

Documents and predictable fields

Extract invoice line items, support-ticket metadata or standardized record fields. Validate against a schema and reconcile numeric totals before committing records. If complex ambiguity or expert interpretation dominates, compare Sol.

02 · CLASSIFICATION

High-volume triage and routing

Label messages, summarize user feedback and route incidents. Measure accuracy per class—especially rare, sensitive or costly-to-misclassify categories—rather than optimizing solely for cost per request.

03 · TEMPLATED COMMUNICATION

Drafts with clear requirements

Generate standardized replies, FAQs and operational summaries using an approved knowledge base. Keep policy and source-of-truth content explicit. Human review remains important for high-stakes advice.

04 · CODE SUPPORT

Small, verifiable coding tasks

Try boilerplate generation, straightforward patches, lint suggestions or test drafting. Use automated tests; escalate multi-file debugging, hard architecture or fragile agent workflows to 6.1 Sol or Astra when justified.

05 · TOOL-ENABLED AUTOMATION

Focused agents with guardrails

Luna supports function calls and built-in tools through the Responses API. Use constrained tool contracts, retries with budgets, injection defenses and explicit approvals for irreversible actions.

06 · LONG DOCUMENT PROCESSING

Big contexts with financial guardrails

Luna's 1.05M context can be useful for large text, but a 272K+ request triggers the higher price band. Test whether retrieval or chunking can retain quality at lower input cost.

A practical selection sequence

  1. Define success. Collect real examples with expected results, hard cases and privacy constraints.
  2. Measure Luna first on focused tasks: accuracy, latency, billed tokens, retry rate and tool success.
  3. Compare 6.1 Sol on tasks Luna misses; calculate incremental cost per corrected outcome.
  4. Test Astra only where needed for demanding or high-error-cost work; avoid a blanket upgrade.
  5. Recheck in production. Monitor prompt distribution, context threshold crossings, cached usage and data drift.

DEVELOPER DOCUMENTATION

How to use GPT-6 Luna in the OpenAI API.

The API model ID is gpt-6-luna. For normal production reasoning and tool integrations, prefer the Responses API.

from openai import OpenAI

client = OpenAI()  # Set OPENAI_API_KEY in your environment
response = client.responses.create(
    model="gpt-6-luna",
    reasoning={"effort": "medium"},
    input="Classify this support message and explain the label briefly.",
)
print(response.output_text)
REASONING CONFIGURATION

none, low, medium, high, xhigh, max

OpenAI documents medium as the default. none can be economical for easy tasks; stronger effort can help some work but may increase output usage and latency. Evaluate the entire workflow.

ENDPOINT CONSTRAINT

Responses for reasoning with tools

Tool calling is supported through Responses. If you must use Chat Completions, function calling on Luna requires reasoning_effort="none". These surfaces are not interchangeable.

INPUT AND OUTPUT

Text and images in; text out

Use text or image inputs for inspection and response generation. This is not a speech synthesis, realtime audio or video-generation model; those need other endpoints/models.

STRUCTURED OUTPUTS

Schema-friendly workflows

OpenAI lists structured outputs, streaming and function calling. Apply schema validation and downstream consistency checks; format validity by itself does not prove the underlying answer is correct.

Prompting advice: keep instructions explicit, provide a handful of representative edge cases when useful, separate data from instructions and require a verifiable output contract. For repeated system prompts, keep prefix content stable to improve the chance of cache reuse, then confirm hits in usage reports.

Parameter compatibility: with reasoning effort other than none, OpenAI advises removing temperature, top_p and certain token-logprob settings that are not supported. Consult the GPT-6 migration guide before copying parameters from older integrations.

BENCHMARKS AND EVIDENCE

How to interpret GPT-6 Luna benchmarks.

SXF retains its separately maintained model-evaluation observations below, including evaluator names, benchmark versions, reasoning settings and evidence links. Use those cards to inspect individual measurements rather than treating one score as a universal ranking against Sol or Astra.

For purchasing or architecture decisions, compare real workflows under identical conditions: same prompt data, context length, reasoning effort, allowed tools, success criteria and privacy policy. Record cost per accepted task and latency per accepted task. A cheaper per-token model is valuable only if it performs the required work reliably.

Long-context benchmarks are especially easy to overgeneralize. A model can accept large input while still missing relevant details or making unsupported inferences. Check source citation fidelity and exact retrieval, not just whether it can ingest the document.

LIMITS AND CAVEATS

What GPT-6 Luna's spec sheet does not guarantee.

01

Context is not perfect recall. A 1.05M window gives capacity, not a promise that every detail is recovered or correctly reasoned about.

02

Cheap tokens do not prove cheap outcomes. Retries, tool costs, reviews and escalations must be included when modeling total economics.

03

Reasoning is configurable. Higher settings may alter task quality, output use and speed; use measured configurations, not one effort level for every request.

04

The long-context boundary is abrupt. Monitor the entire input count because one additional token beyond 272K changes the rate applied to the whole request.

05

Tools need operational controls. Sandbox execution, limit privileges, verify external content and require approval for sensitive actions.

06

API and ChatGPT access differ. Consumer product names, quotas and subscriptions should not be confused with OpenAI API billing or processing mode availability.

FREQUENTLY ASKED QUESTIONS

GPT-6 Luna FAQ.

What is GPT-6 Luna?

GPT-6 Luna is OpenAI's efficient GPT-6 tier for focused reasoning and high-volume, cost-sensitive tasks. It accepts text and image input and generates text output.

How much does GPT-6 Luna cost?

Standard API pricing for requests up to 272,000 input tokens is $0.10 input, $0.01 cached input, $0.125 cache write and $0.50 output per million tokens. Above 272K input tokens, rates increase across the entire request.

What is the GPT-6 Luna model ID?

The exact API model ID is gpt-6-luna.

What is the GPT-6 Luna context window?

1,050,000 input tokens with a maximum of 128,000 output tokens, according to OpenAI's published model card.

What happens above 272K input tokens?

For a request with more than 272,000 input tokens, the whole request is billed at double the input and cache rates and 1.5 times the output rate. The trigger is strictly greater than 272K.

How much does a long-context Luna request cost?

At Standard rates a request with 300,000 uncached input and 20,000 output tokens costs $0.075 before tool or regional-processing fees.

How does GPT-6 Luna compare with GPT-6.1 Sol?

Luna has lower Standard token prices and is positioned for efficiency. GPT-6.1 Sol is the newer middle tier for more complex coding, agentic tasks and professional work. Test both on actual workloads to decide.

How does GPT-6 Luna compare with Astra?

GPT-6 Astra targets the highest-capability GPT-6 tasks while Luna prioritizes lower per-token cost. Astra's Standard short-context uncached input and output rates are 100 times Luna's.

Does Luna support reasoning effort none?

Yes. GPT-6 Luna supports none, low, medium, high, xhigh and max, with medium as the default.

Does GPT-6 Luna support the Responses API?

Yes. The Responses API supports Luna reasoning and tools. In Chat Completions, function calling is supported with reasoning effort set to none.

What is GPT-6 Luna's knowledge cutoff?

OpenAI publishes May 18, 2026 as the knowledge cutoff. Use retrieval or tools for information after that date.

Is GPT-6 Luna good for coding?

It can be useful for focused, testable coding tasks. For complex multi-file debugging and high-risk changes, compare GPT-6.1 Sol or Astra using your own unit tests and acceptance criteria.

Does GPT-6 Luna accept images?

Yes. Its published modalities include text and image input with text output; it is not a dedicated voice or video-generation endpoint.

Is GPT-6 Luna cheaper than GPT-6 Sol?

On Standard short-context list rates, Luna is 20 times cheaper per uncached input and output token than both original GPT-6 Sol and newer GPT-6.1 Sol. Actual task cost depends on retries, reasoning, tools, caching and outcome quality.

Can I use prompt caching with Luna?

Yes. OpenAI lists separate cached-input and cache-write rates. A cache hit and a cache write are not the same; monitor billed usage in your deployment.
