MISTRAL OCR 4.1 / DIRECT ANSWER

What is Mistral OCR 4.1?

Mistral OCR 4.1 is Mistral AI's generally available, hosted Document AI optical character recognition API for turning PDFs and images into searchable text and structured document content. Its pinned model ID is mistral-ocr-4-1, available through POST /v1/ocr or client.ocr.process(). It handles tables, headings, formulas, images, layout regions and multilingual documents rather than acting as a general conversational model.

The defining OCR 4.1 features are paragraph-level bounding boxes, document block-type labels and page-, block- or word-level confidence scores. Standard OCR processing is published at $4 per 1,000 pages ($0.004/page); the OCR 4.1 model card separately lists $5 per 1,000 annotated pages ($0.005/page). Those are distinct published processing categories, not a flat fee per chat token.

VERSION-PINNED API QUICKSTART

How to use Mistral OCR 4.1 API with Python for PDF and image extraction.

Install the official mistralai Python SDK and configure MISTRAL_API_KEY on your server. For reproducibility, pin mistral-ocr-4-1 rather than relying on the mutable mistral-ocr-latest alias. The documented method is client.ocr.process() through the /v1/ocr service.

import os
from mistralai.client import Mistral

client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])

response = client.ocr.process(
    model="mistral-ocr-4-1",
    document={
        "type": "document_url",
        "document_url": "https://arxiv.org/pdf/2201.04234"
    },
    table_format="html",
    include_blocks=True,
    confidence_scores_granularity="block"
)

for page in response.pages:
    print(f"PAGE {page.index}")
    print(page.markdown)
    for block in (page.blocks or []):
        print(block.type, block.content)

print(response.usage_info)

This example uses a public test PDF URL; it is not a benchmark run. For private files use Mistral's upload or permitted Base64 request paths instead of publishing a private PDF at a public URL. Never embed an API secret in client-side JavaScript. Verify MIME types, document permission and the actual response schema before automating downstream actions.

For complete request and upload details, consult Mistral's OCR quickstart and the OCR endpoint reference. In production, inspect each page's markdown, tables, images, blocks and usage_info independently—do not assume an OCR call creates a validated business record.

DOCUMENT STRUCTURE

OCR 4.1 bounding boxes, confidence scores, tables and reading order.

OCR 4.1 can return a blocks array when include_blocks=True. Mistral documents coordinates top_left_x, top_left_y, bottom_right_x and bottom_right_y, the type label, and content. Available labels include text, title, list, table, image, equation, caption, code, references, aside_text, header, footer and signature.

How to choose OCR 4.1 extraction settings and verify output
RequirementRequest settingWhat the response actually proves
Paragraph and title coordinatesinclude_blocks=TruePredicted region locations; not guaranteed reading-order correctness

Document header/footerextract_header=True, extract_footer=TrueFields returned separately; confirm nothing meaningful was omitted
Page-level uncertaintyconfidence_scores_granularity="page"Aggregate scores only; no cell-by-cell factual guarantee
Block confidence"block" with include_blocks=TrueBlock average/minimum content and block-type scores where defined
Word confidence"word"Word-level scores on pages/tables; different from block-score mode

Confidence is not accuracy: a high score can still accompany an incorrect invoice amount, omitted negative sign or merged table cell. Conversely, some non-text regions can have null content confidence. Use human-reviewed thresholds calibrated on your own scanned documents, not a universal “above 90% = correct” rule.

Why Markdown-only OCR can lose important evidence

Mistral's Markdown output may include placeholders such as ![img-0.jpeg](img-0.jpeg) or [tbl-3.html](tbl-3.html). Resolve the accompanying images and tables arrays before indexing; otherwise retrieval may silently lose charts or tables. For document-search architecture, keep page ID, bounding box, original file ID and parsed content tied together. Related: SXF vector databases for RAG and RAG vs fine-tuning vs long-context design.

DOCUMENT AI VS BASIC OCR

Basic OCR vs annotated document extraction: what should you pay for?

Basic OCR transcribes a page and extracts document structure. Document annotations add schema-guided information extraction, for example returning an invoice number, due date, currency and supplier as validated application fields. Mistral's annotations guide distinguishes document annotations from box annotations (region-level interpretation such as charts).

Do not assume include_blocks=True automatically means the annotated-page price. The model card lists a separate annotated-page amount, but the actual billing basis for combinations of OCR and annotation requests must be checked against the API and account invoice. In a production workflow, validate all schema fields and currency/number formats; document OCR and document understanding are stages, not equivalent guarantees.

PRACTICAL DOCUMENT PIPELINES

Using Mistral OCR 4.1 for searchable PDFs, invoices and RAG.

  1. Ingest and authorize: receive a PDF with explicit access rights, validate its file type and size, and store a stable document ID.
  2. Run OCR: use pinned mistral-ocr-4-1, preserving page indices and handling failed or skipped pages explicitly.
  3. Preserve structure: map tables, formulas, images and bounding boxes back to source pages; do not index Markdown placeholders as if they were the extracted content.
  4. Normalize and review: check dates, amount signs, currency, identifiers, redacted content and selected low-confidence regions against the original scan.
  5. Chunk and retrieve: embed chunks with page IDs and access-control tags; apply tenant filters before semantic/vector search and log provenance for final answers.
  6. Measure: separately report text accuracy, table-cell fidelity, missing-data rate, processing latency and total cost per approved document.

OCR extraction is a preprocessing step, not a substitute for provenance-aware retrieval. If OCR output is later sent to an AI agent, treat text recovered from third-party documents as untrusted content, not as system instructions. Apply authentication, authorization and the controls in the SXF prompt injection guide and AI agent security guide.

DEVELOPER SEARCH QUESTIONS

Mistral OCR 4.1 FAQ: model ID, PDF API, page price and bounding boxes.

What is the Mistral OCR 4.1 API model ID?

Use mistral-ocr-4-1 via client.ocr.process() or POST /v1/ocr. The alias mistral-ocr-latest currently resolves to OCR 4.1, but it may change over time.

How much does Mistral OCR 4.1 cost per page?

Mistral publishes $4 per 1,000 Standard OCR pages ($0.004/page) and separately lists $5 per 1,000 annotated pages ($0.005/page). Confirm your actual annotation and Batch billing eligibility.

Can Mistral OCR 4.1 extract tables from PDF?

Yes. Set table_format="markdown" or "html" to return separate table structures. Check row, column and value accuracy against the source.

Does OCR 4.1 return bounding boxes and coordinates?

Yes. With include_blocks=True, page blocks include structural labels, bounding box coordinates and extracted content in reading order.

What confidence scores does OCR 4.1 support?

Use confidence_scores_granularity with "page", "block" or "word". Block scores require include_blocks=True; scores guide review but are not accuracy guarantees.

Is Mistral OCR 4.1 an open-source model?

No. Mistral presents OCR 4.1 as a generally available Premier hosted service. Do not conflate its Document AI API with Mistral's separately licensed open-weight language models.

What changed from OCR 4.0 to OCR 4.1?

OCR 4.1 adds block-granularity confidence scores. Mistral's changelog lists OCR 4.0 as deprecated, recommends OCR 4.1, and states the same Standard page price.

Can OCR 4.1 power a RAG PDF search system?

Yes, as the text-and-structure extraction stage. A reliable RAG system must additionally preserve provenance, validate tables, control user permissions and evaluate retrieval quality.
