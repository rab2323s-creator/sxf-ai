DIRECT ANSWER

What is LFM2.5-24B-A2B?

LFM2.5-24B-A2B is Liquid AI's text-only, mixture-of-experts (MoE) reasoning model designed for local agents and tool use. It contains about 24B total parameters, of which 2.45B are active for each token. Released on October 13, 2026, it is the largest final member of the LFM2.5 series. The post-trained checkpoint is tuned for multi-step tool workflows; a separate base model supports customization. Liquid AI's launch announcement provides the architectural and evaluation background.

It is not a vision-language or speech model. Its documented interface is text in, text out. A tool-using agent can combine it with external code, web retrieval or document processing—but those capabilities depend on the agent harness, permissions, connectors and prompt format, not on native image or microphone input.

Best fit: local instruction-following and agentic automation where tool reliability, data control and decode efficiency matter. Less certain: knowledge-intensive questions, challenging web navigation, complex software engineering and low-memory laptops running long contexts.

ARCHITECTURE EXPLAINED

24B total vs 2.45B active: how the MoE model works

The sparse MoE router chooses four of 64 experts at each applicable expert block for a token. This reduces work per token relative to evaluating all experts, but every expert still occupies weight storage unless the runtime offloads or streams it. Lower computation does not imply the same RAM requirements as a dense 2B model.

01 / INPUTTokenize

Text is converted with the updated 128K-token vocabulary.

02 / MIXHybrid layers

30 gated short-convolution blocks and 10 GQA blocks process context.

03 / ROUTESelect top 4 experts

Sparse expert paths execute for each token in MoE blocks.

04 / REASONGenerate answer

The post-trained model generates reasoning and an eventual final answer; a harness controls tool execution.

Compared with LFM2-24B-A2B, the later LFM2.5 release extends context from 32,768 to 131,072, expands vocabulary from roughly 65K to 128K, and adds more pretraining and agentic post-training while retaining the 40-layer hybrid design. The October announcement describes a five-stage post-training process including SFT, distillation and agentic reinforcement learning; it also reports reward-hacking during training and tighter evaluation sandboxes.

The official Q4_0 Quantization-Aware Distillation (QAD) variant has a distinct fine-tuned checkpoint designed to recover quantization accuracy; it is not necessarily equivalent to naive Q4_0 quantization. As a starting point, Q4_K_M weighs about 14.5 GB, while BF16 is around 48 GB. A 16GB laptop may not have adequate headroom to fully load a 14.5GB weight file plus runtime, OS and KV cache.

Why the model may not fit despite “2B active”

For MoE inference, the full collection of experts must be available in RAM/VRAM or offloaded to slower storage. The active parameter count primarily predicts a portion of compute, not how many bytes the entire model occupies. Very long contexts can add substantial cache pressure even when weight quantization is aggressive. Use actual peak RSS and GPU allocation measurements to confirm your deployment.

OFFICIAL CHECKPOINTS AND COMMANDS

How to run LFM2.5-24B-A2B locally with llama.cpp

Use a recent llama.cpp build supporting lfm2moe, enough memory for the selected quantization, and the official model repo. This command follows Liquid AI's published GGUF instructions and includes its recommended generation preset:

Terminal · official GGUF
llama-cli -hf LiquidAI/LFM2.5-24B-A2B-GGUF \
  --temp 0.1 --top-k 50 --repeat-penalty 1.05

To select the separately trained QAD variant explicitly:

Terminal · first-party QAD Q4_0
llama-cli -hf LiquidAI/LFM2.5-24B-A2B-GGUF \
  --hf-file LFM2.5-24B-A2B-QAD-Q4_0.gguf \
  --temp 0.1 --top-k 50 --repeat-penalty 1.05

MLX, vLLM, SGLang and FP8

Liquid AI lists day-one support for MLX on Apple Silicon, vLLM / SGLang for GPU serving, and cross-platform ONNX. For multi-request serving, use the native safetensors model or the official FP8 checkpoint according to runtime support. Do not use GGUF sample commands with a native vLLM model server without converting the setup.

To make a private agent, connect a trusted local inference endpoint to an agent harness and narrowly scoped tools. Require confirmation before shell execution, deleting files, sending messages or authorizing payments; save an audit trail and measure tool-call correctness separately from text fluency. Local weights do not automatically make a tool-enabled agent safe.

APPLICATION ENGINEERING

Best uses for LFM2.5-24B-A2B local agents

01 · TOOL AUTOMATION

Local workflow agent

Parse instructions, select a small whitelisted tool, confirm risky actions and record outcomes. Evaluate the actual tool-call success rate, not whether the reasoning narrative sounds plausible.

02 · PRIVATE DATA

On-device document assistant

Pair local weights with retrieval over permitted documents. Verify citations against source passages, especially on knowledge-heavy requests where the model trails stronger competitors.

03 · STRUCTURED OUTPUT

Text extraction pipeline

Use a schema validator, retries and deterministic acceptance checks. Report exact field accuracy and failure types on held-out customer data.

04 · MULTILINGUAL

International support routing

The expanded tokenizer supports a broader non-Latin vocabulary. Test Arabic, Chinese and other target languages with native examples; vocabulary size does not guarantee language parity.

SXF reproducible local-agent test protocol

  1. Pick 20–50 representative, permission-safe tasks and record expected outcomes.
  2. Freeze the model revision, quantization, prompt template, sampler, context length and tool definitions.
  3. Run tasks with and without external retrieval; record success, tool calls, retries, latency and failure cost.
  4. Repeat each test under controlled conditions, including adversarial requests and attempts to bypass tool permissions.
  5. Only then compare hardware cost and throughput; vendor performance numbers are not task-success guarantees.

WHAT NOT TO ASSUME

Limitations, licensing and benchmark caveats

  • 24B still needs memory: only 2.45B parameters are active per token, but stored expert weights are much larger.
  • Long context costs RAM: 131,072 tokens is a model specification, not a verified 131K-token laptop configuration or guarantee of perfect recall.
  • Text-only: images and audio require a separate model or preprocessing components.
  • Reasoning text is not proof: explicit reasoning generation can still contain errors and may consume additional output tokens.
  • Different benchmark domains disagree: its published agentic strengths do not translate automatically to expert Q&A, difficult browsing and coding.
  • Safety: Liquid AI reports discovering reward-hacking during training; restrict tools and revalidate behavior in your own environment.
  • Open-weight license: review LFM Open License v1.0; accessible weights are not automatically unrestricted open-source software.
  • API pricing changes: published launch rates and credits may not reflect later billing or regional availability.

DIRECT SEARCH ANSWERS

LFM2.5-24B-A2B frequently asked questions

What is LFM2.5-24B-A2B?

Liquid AI's text-only 24B-parameter MoE reasoning model with approximately 2.45B active parameters per token, released on October 13, 2026 for tool-using local agents.

Why is it called A2B if 2.45B parameters are active?

A2B is a rounded name. The official model card reports 2.45B active and 24.0B total parameters. The full weight set still needs memory or offloading.

What is the context length?

131,072 tokens as published by Liquid AI. Actual machine capacity and long-context retrieval quality require separate verification.

Can I run it with 16 GB RAM?

Its official Q4_0 file is about 13.6 GB, and Q4_K_M is about 14.5 GB, leaving little room for the OS and KV cache in a 16 GB configuration. Full on-device fit is not guaranteed.

Which GGUF quantization should I try first?

Choose based on available memory and quality requirements. Liquid AI publishes Q4_0/QAD, Q4_K_M, Q5_K_M, Q6_K and higher-precision versions. The SXF fit tool compares their weight sizes but does not predict total RAM usage.

Is it faster than Qwen3.6-35B-A3B?

Liquid AI claims up to 1.7 times faster on certain edge measurements; benchmark accuracy varies by task. Qwen wins some of the vendor's WebArena, knowledge and coding evaluations.

Can I run it with llama.cpp?

Yes, using a compatible recent build and the official LiquidAI GGUF repository. A verified command and sampling preset are shown above.

Does it support image input?

No. It is a text-only reasoning model, separate from Liquid AI's vision-language family.

How much is the API?

At launch, Liquid AI reported $0.10 per million input tokens, $0.05 cached input and $1.00 output. Verify current rates with Liquid Console.

Is it commercially unrestricted open-source?

It is distributed as open weights under LFM Open License v1.0. Read that license's commercial and redistribution conditions before deploying.

What changed from LFM2-24B-A2B?

The successor offers 131,072 instead of 32,768 context tokens, a 128K instead of roughly 65K vocabulary, and more reasoning/agent training.

Is there a separately trainable base model?

Yes. Liquid AI distributes LFM2.5-24B-A2B-Base for customization, separately from the post-trained agent model.
