LFM3 models:
small models, specialized intelligence.

LFM3 is Liquid AI's October 27, 2026 open-weight model family: six roughly 2B-class variants for text, image, video, speech, combined multimodal input and structured decisions. Compare real model specifications, locally runnable examples, vendor benchmark results and a unique SXF model chooser.

THE DIRECT ANSWER

What is LFM3 by Liquid AI?

LFM3 is a family of lightweight foundation models built on Liquid AI's new 1.73-billion-parameter, 24-layer tri-hybrid backbone. The October 27, 2026 launch included six post-trained variants for language, vision, audio, omni experiences and decision-making, plus a separate base checkpoint for adaptation. Rather than requiring one large general-purpose network to handle every job, the family offers a small checkpoint matched to each input/output contract.

All variants trace back to LFM3-1.7B-Base. Specialized vision and audio branches add their own encoders and components. The decision models are derived from the vision or omni branches and answer questions through calibrated, typed outputs without generating a chat response token by token. This distinction is essential when comparing models, context limits, memory and accuracy.

Liquid AI says the 1.7B base was trained on 22 trillion tokens, including a curated final 3.5T-token mid-training stage emphasizing agentic traces and tool calls. These are developer-reported training details, not independently audited data. Read the technical release notes ↗

WHAT CHANGED UNDER THE HOOD

LFM3 tri-hybrid architecture: 13 + 5 + 6 layers

Liquid AI's 24-layer LFM3 language backbone mixes 13 gated short convolutions, 5 sliding-window attention layers (256-token local window) and 6 global attention layers. These are different processing operators within a shared backbone, not three separate full-size models.

13 / 24Gated short convolutions
Efficient local sequence mixing · kernel size 7
5 / 24Sliding-window attention
Local attention, 256-token window
6 / 24Global attention
Longer-range token interactions

Other changes include head-wise gated attention, partial RoPE on global-attention heads and sandwich normalization. The vocabulary has 128,000 tokens. Liquid AI used a hardware-aware search across 14 device/backend configurations; the company reports LFM3-1.7B is about 25% faster than the comparison baseline per parameter at 8K context. That is not a universal 25% application speed gain. Architecture evidence ↗

Practical implication: the text model targets efficient long-context inference, while the vision and audio variants add modality-specific encoders. A 256K model-card limit is a maximum supported context, not proof of accurate recall at every position.

WEIGHTS ARE NOT TOTAL MEMORY

Can LFM3 run locally? RAM, VRAM and quantization

Liquid AI says the LFM3-1.7B text model fits in about 1 GB with 4-bit weights. That is the model-weights footprint, not a minimum system-RAM requirement. Token buffers, context length, KV cache, execution kernels and runtime overhead add memory. Vision and audio checkpoints also need encoders, decoders and preprocessing.

TEXT · 4-BIT~1 GB

Vendor-reported compressed weight scale. Not total RAM; actual file format and runtime matter.

TEXT · CONTEXT256K max

Published supported window for LFM3-1.7B; a huge context still incurs memory and latency costs.

VISION128K

Published LFM3-VL-2B context; high-resolution images and video frames add work.

AUDIO32K

Published LFM3-Audio-2B context. Check audio buffers and speech codec separately.

Runtime choices: the official text model card lists BF16 with vLLM, SGLang or Transformers; quantized GGUF for llama.cpp/Ollama/LM Studio; and MLX for Apple silicon. Availability and instructions differ by variant. Do not assume the same quantization support, throughput, context length or speed across all six checkpoints.

Before buying hardware, measure the exact checkpoint plus tokenizer, vision/audio preprocessing, prompt size, batch size and peak memory. A Raspberry Pi or phone appearing in the developer's architecture-search devices is not a guarantee that every multimodal variant works comfortably on every such device.

SOURCE-ALIGNED QUICK START

How to run LFM3 locally with Python

The official LFM3 release includes starter code for the text model. In a Python environment with the required dependencies and compatible hardware, load the model from Hugging Face. Use version-pinned environments for production; models using trust_remote_code=True execute repository-provided Python code, so review and pin the model revision before using it with private data.

Terminal · install
python -m pip install -U transformers accelerate
Python · text inference
from transformers import pipeline

generator = pipeline(
    "text-generation",
    model="LiquidAI/LFM3-1.7B",
    trust_remote_code=True,
)
messages = [
    {"role": "user", "content": "Return JSON with a title and one-sentence summary of: local AI models."}
]
result = generator(
    messages,
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.1,
    max_new_tokens=512,
)
print(result[0]["generated_text"][-1]["content"])

For images and video, load LiquidAI/LFM3-VL-2B with its official processor; Liquid AI documents transformers>=5.21.0 and vision dependencies. For speech, use the audio model's processor and LiquidCodec (documented transformers>=5.20.2). For combined inputs, follow the omni model card; swapping the text checkpoint for a multimodal one in this simple pipeline is insufficient.

BUILD SPECIALIST MODELS

How to fine-tune LFM3 for your own domain

Liquid AI provides examples of single-GPU fine-tuning across the family. Choose the post-trained variant whose interface fits the task, or start from LFM3-1.7B-Base if your project needs its own training objective. The published notebooks include supervised fine-tuning (SFT), direct preference optimization (DPO), group relative policy optimization (GRPO) and continued pretraining (CPT)—not every technique is equally appropriate for every task.

SXF evaluation protocol: (1) freeze a held-out test set; (2) save model revision, runtime and preprocessing settings; (3) report a baseline before tuning; (4) fine-tune on non-overlapping examples; (5) compare performance and cost against the same acceptance criteria; (6) evaluate failure cases, safety and calibration. A specialized model that improves one score but fails under distribution shift is not yet deployment-ready.

Vendor example: Liquid AI adapted LFM3-VL-2B to inspect wind-turbine blade images using around 3,000 training photos and tested on around 1,400 held-out images. The company reports classification accuracy reaching 67% after tuning, but this result is tied to that dataset and procedure—not a generic improvement guarantee. Methodology and project details ↗

CHECK BEFORE DEPLOYMENT

LFM3 limitations, safety and open-weight licensing

  • Small model limits: LFM3-1.7B is suited to narrow agents but the official model card cautions against complex multi-step reasoning and agentic coding. Use retrieval for knowledge-intensive tasks.
  • Modality-specific contexts: vision and speech branches do not inherit the text variant's 256K context window. Verify each model card and engine.
  • Vendor measurements: LFM3 accuracy, speed, fine-tuning and token counts here reflect Liquid AI's reported setups. SXF has not run an independent LFM3 benchmark.
  • No universal hardware promise: a 1 GB quantized weight claim is not proof that an entire agent, image pipeline or 256K KV cache fits in 1 GB of device RAM.
  • Licensing: Hugging Face cards label the checkpoints lfm1.0 / LFM Open License v1.0. Open weights are not necessarily an unrestricted OSI-approved open-source license; review conditions before redistribution or commercial use.
  • Privacy and security: on-device inference can keep raw data on a device, but downloaded remote code, tool permissions, logs and external inference calls still require review.
  • Decision calibration: a probability score is not automatically a correct probability after deployment or distribution shift. Test on target population data and set thresholds against error costs.

SEARCH QUESTIONS ANSWERED

Frequently asked questions about Liquid AI LFM3

What is LFM3 by Liquid AI?

A six-model, open-weight family announced on October 27, 2026, built around a compact 1.73B-parameter tri-hybrid backbone. Its branches handle text, vision, audio, omni and typed decisions.

Is LFM3 one model or six?

The first release comprises six specialized post-trained models. LFM3-1.7B-Base is a separate pre-trained starting checkpoint.

What is the LFM3 context window?

It varies. LFM3-1.7B specifies 256K tokens; LFM3-VL-2B specifies 128K; LFM3-Audio-2B specifies 32K. Check the specific model card for other branches.

Can I run LFM3 on a laptop?

Liquid AI targets local inference and says text weights occupy about 1 GB at 4-bit precision. Actual memory is higher and depends on context, runtime, encoders and batch size.

Is LFM3 open-source?

The family is distributed as open weights under LFM Open License v1.0. Review the license conditions; open weights do not automatically mean an OSI-approved unrestricted open-source license.

Can I fine-tune LFM3 on one GPU?

Liquid AI provides single-GPU examples and tutorials. The actual device memory and time requirements depend on the model, precision, data and fine-tuning method.

What improved between LFM3 and LFM2.5?

Liquid AI reports greater capability per parameter, a tri-hybrid backbone, a new vision encoder with video input, new audio components and specialized decision branches. Published comparisons are vendor-reported.

Which LFM3 model handles voice and images?

LFM3-Omni-2B accepts text, image, video and audio and produces text or speech. For typed decisions about voice and visual evidence, consider d1-Omni-2B.

Does the LFM3 API have a permanent free tier?

The release confirms Hugging Face weights, a Playground and Liquid AI API access, but not a permanent universal free tier. Consult the current service pricing and availability.
