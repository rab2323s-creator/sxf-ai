GPT-6.1 RELEASE REFERENCE · PRIMARY SOURCES

What is GPT-6.1, and which models are available?

GPT-6.1 is the newer release in OpenAI's GPT-6 series, introduced on September 29, 2026 with GPT-6.1 Sol. Its purpose is to deliver more of the capability of GPT-6 Astra in a lower-cost Sol tier. OpenAI positions the update for demanding software engineering, computer-use agents, multi-step professional workflows, scientific research and factual reasoning.

There is an important distinction between a release name and an API model ID. "GPT-6.1" refers to this generation/update, while the currently documented named model is gpt-6.1-sol. Do not assume gpt-6.1, gpt-6.1-astra or gpt-6.1-luna is a working public API model identifier without an official OpenAI model card.

This is SXF's GPT-6.1 release and changes hub: discover what launched, which editions are officially documented, what improved over original GPT-6 Sol, what developers need to migrate, and where to find source evidence. For full 1.05M-context specifications, per-tier rates, token math, example requests and model-level benchmarking, read the dedicated GPT-6.1 Sol technical reference.

WHAT CHANGED FROM GPT-6 SOL

GPT-6.1 release changes in coding, agents and cost.

These are provider-documented release improvements, not a promise that every individual prompt becomes faster or more accurate.

01 / CODING

Stronger multi-step software engineering

OpenAI reports higher performance on DeepSWE 1.1, including a 6.4 percentage-point advantage over the original Sol's best result in its published configuration. This helps explain the newer model's positioning for real codebases.

02 / COMPUTER USE

More capable browser and desktop agents

In OpenAI's OSWorld 2.0 offline evaluation, 6.1 Sol improved seven percentage points over the earlier Sol at maximum reasoning effort. Permission boundaries, tool success and application-specific reliability still need testing.

03 / PROFESSIONAL WORK

Better complex documents and workflow execution

OpenAI describes improvements on GDP.pdf and AutomationBench. On AutomationBench, it reports a 4.8 percentage-point improvement over GPT-6 Sol at the same medium effort, reflecting stronger multi-tool execution in those test conditions.

04 / FACTUALITY

Fewer errors in a deliberately difficult test

OpenAI reports a drop in responses containing factual errors from 11.4% to 7.7% at low reasoning effort in a dataset of prior user-flagged mistakes. These prompts are intentionally challenging, not representative of ordinary traffic.

05 / PROMPT CACHE

Half the cached-input token rate

Standard cached input decreased from $0.2 to $0.1 per million short-context tokens—a 50% reduction in the cached-input rate. The uncached input and output list rates remained $2 and $10.

06 / AGENT DESIGN

Responses API, tools and subagents

OpenAI's September 29 API changelog added 6.1 Sol, documented Responses-based tool calling and introduced Multi-agent support in beta. Developers should verify endpoint and feature availability rather than assuming compatibility from the predecessor.

UPGRADING EXISTING INTEGRATIONS

Migration guide: GPT-6 Sol → GPT-6.1 Sol.

An upgraded model identifier does not guarantee identical prompt, tool and reasoning behavior. Validate the differences before a production switch.

STEP 1

Use the explicit model ID

Change gpt-6-sol to gpt-6.1-sol in an evaluated integration. Avoid an undocumented gpt-6.1 alias.

STEP 2

Check reasoning levels

6.1 Sol supports low, medium, high, xhigh and max, with medium as the default. Unlike old Sol, it does not support none or minimal.

STEP 3

Use Responses for tools

OpenAI documents tool calling on the Responses API for 6.1 Sol. Chat Completions remains supported without tools; do not copy a tool-enabled old-Sol Chat Completions request unchanged.

STEP 4

Measure cache effectiveness

The $0.10 cached-input rate benefits real cache hits. Observe billed cached tokens; do not count new uncached prompt tokens as cached. Cache writes and tools have separate fees.

STEP 5

Review long-context billing

More than 272,000 prompt-input tokens triggers 2× input/cache and 1.5× output rates for the entire request. The 1.05M token window is a serving limit, not a single low-price band.

STEP 6

Re-run safety and task evaluations

Test coding success, retrieval fidelity, injection resistance, tool authorization, response time and cost per accepted result. Use human review for high-stakes or irreversible steps.

from openai import OpenAI

client = OpenAI()  # Set OPENAI_API_KEY in the environment

response = client.responses.create(
    model="gpt-6.1-sol",
    reasoning={"effort": "medium"},
    input="Review this code change and identify its main risks.",
)
print(response.output_text)

The code demonstrates a model-specific Responses API request. For full API parameter tables, tool constraints and deployment settings, see the GPT-6.1 Sol model card and OpenAI's current GPT-6 developer guidance.

RELEASE QUESTIONS

GPT-6.1 FAQ: models, release date and migration.

What is GPT-6.1?

GPT-6.1 is the updated GPT-6 release that launched with GPT-6.1 Sol on September 29, 2026. OpenAI positions the newer Sol model for coding, computer use and complex professional work.

When did GPT-6.1 come out?

OpenAI announced GPT-6.1 Sol on September 29, 2026, including an official API model card and changelog entry.

Which GPT-6.1 model variants are available?

The official GPT-6.1 model documented in the sources reviewed here is GPT-6.1 Sol. The existence of GPT-6 Astra, GPT-6 Luna or original GPT-6 Sol does not make them GPT-6.1 variants.

Is there a GPT-6.1 Astra or GPT-6.1 Luna?

The cited public model documentation establishes GPT-6.1 Sol, not separately documented GPT-6.1 Astra or GPT-6.1 Luna API identities. Do not assume such model IDs work without an official release.

What is the GPT-6.1 API model ID?

Use gpt-6.1-sol. This page covers the release; the separate SXF GPT-6.1 Sol model reference contains the technical model details.

What changed from GPT-6 Sol to GPT-6.1 Sol?

OpenAI reports stronger coding, computer-use, multi-tool professional workflows and factuality on specified evaluations, with cached input rates reduced from $0.20 to $0.10 per million short-context tokens.

Is GPT-6.1 more expensive than GPT-6 Sol?

Standard short-context uncached input and output rates remain $2 and $10 per million tokens. The 6.1 Sol cached-input read rate is $0.10, half the original Sol's $0.20.

What is the GPT-6.1 Sol context window?

GPT-6.1 Sol has a 1,050,000-token input window and a 128,000-token maximum output, according to the official model card.

Can GPT-6.1 Sol use reasoning effort none?

No. The model supports low, medium, high, xhigh and max with medium as its default. Original GPT-6 Sol also supported none, so integrations must review this setting.

Can I use GPT-6.1 Sol with Chat Completions?

The API documentation supports Chat Completions without tool calling. For tools with GPT-6.1 Sol, use the Responses API.

How does long-context pricing work for GPT-6.1?

Requests with more than 272,000 input tokens use twice the input, cached input and cache-write rates plus 1.5 times the output rate across the whole request.

Is GPT-6.1 available in ChatGPT?

The September 29 launch said 6.1 Sol was available in the API, Codex and ChatGPT Work for eligible users, but not yet in Chat at launch. Treat that as a launch-day statement and verify current product availability.

Is GPT-6.1 Sol better than Astra?

OpenAI positions GPT-6.1 Sol near Astra for some demanding tasks at lower Standard list prices. The best model depends on quality, tool success, context, latency and cost per accepted task.

Where can I see full GPT-6.1 pricing and API examples?

Use the dedicated /models/gpt-6-1-sol/ model reference. This release page focuses on what changed and which GPT-6.1 editions are officially documented.
