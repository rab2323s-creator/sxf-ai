MODEL REFERENCE

GPT-5.6 at a glance.

GPT-5.6 is OpenAI’s 2026 model family for production reasoning, coding, knowledge work and agentic workflows. The family has three durable tiers: Sol for flagship capability, Terra for a balance of intelligence and cost, and Luna for efficient high-volume work.

The unsuffixed API alias gpt-5.6 routes to GPT-5.6 Sol. That distinction matters: “GPT-5.6” can refer to the family in product discussions, while the API alias resolves to the Sol tier.

WHAT GPT-5.6 IS

A production reasoning family, not one single model.

OpenAI introduced GPT-5.6 as a family designed to improve performance per dollar across complex work. Sol is the flagship tier and roughly takes the place of the unsuffixed flagship position from earlier GPT-5 families. Terra is the balanced tier, while Luna is optimized for cost-sensitive throughput.

For developers, that means model selection can happen inside one generation without changing the overall API architecture. You can reserve Sol for the tasks where additional reasoning materially changes the result, move repeatable production work to Terra, and use Luna where volume and unit economics dominate.

GPT-5.6 is no longer OpenAI’s newest generation—GPT-6 now occupies that position—but GPT-5.6 remains a current production family with documented API support and distinct lower-cost tiers.

MODEL SELECTION RULE Choose the cheapest tier that passes your real evaluation.

Do not select Sol simply because it is the flagship. Benchmark representative tasks at the reasoning effort you actually plan to use, then compare quality, latency and total token cost.

CAPABILITIES

What GPT-5.6 is designed to do well.

REASONING

Adjustable reasoning effort

GPT-5.6 supports none, low, medium, high, xhigh and max reasoning effort. OpenAI recommends medium as a balanced starting point, then measuring whether higher effort creates a real quality gain.

CODING

Complex software work

OpenAI positions GPT-5.6 for coding and production workflows, with stronger token efficiency and improved frontend design judgment compared with earlier models.

AGENTS

Tool-oriented workflows

The Responses API supports programmatic tool calling, persisted reasoning and agent workflows. Multi-agent orchestration is available in beta across GPT-5.6 models.

VISION

Text + image input

The family accepts image input and text input, with text output. Current model pages do not list native audio or video support for these models.

LONG CONTEXT

1.05M-token context

All three variants list a 1,050,000-token context window and up to 128,000 output tokens, enabling large repositories, document sets and long-running workflows.

EFFICIENCY

Tiered price-performance

Sol, Terra and Luna let the same application route different task classes to different cost envelopes instead of treating every request as a flagship-model request.

REASONING MODES

Standard effort, max effort and Pro mode.

Reasoning effort controls how much reasoning the model applies within a request. GPT-5.6 supports six levels from none through max, and defaults to medium. Lower settings generally favor latency and cost; higher settings are appropriate only when the workload shows a measurable quality benefit.

Pro mode is separate from reasoning effort. Instead of switching to a separate GPT-5.6 Pro model slug, OpenAI documents reasoning.mode: "pro" on the selected GPT-5.6 model. Pro mode performs more model work and is intended for difficult, quality-first tasks that can tolerate higher latency and token usage.

GPT-5.6 also changed reasoning persistence: the family can reuse compatible reasoning across turns within the same GPT-5.6 family. That can matter in long, tool-heavy workflows where goals and assumptions remain stable across multiple calls.

PRACTICAL START Start at medium, then evaluate one level lower and one higher.

OpenAI’s migration guidance explicitly recommends testing the same reasoning level used on an earlier model and one level lower, because GPT-5.6 can often reach the target quality with fewer tokens.

Long-context pricing

OpenAI’s current model pages state that prompts above 272K input tokens are priced at 2× the input rate and 1.5× the output rate for the full request. Cache writes are billed above ordinary uncached input, while cache reads receive a large discount.

Sol promotional pricing

OpenAI currently labels GPT-5.6 Sol’s $4 / $20 rates as promotional pricing available at least through November 21, 2026. Recheck the official model page before building a long-term cost model.

WHICH MODEL?

Choose GPT-5.6 by workload, not by name.

CHOOSE SOL

Quality-first complex work

Use Sol for difficult coding, professional analysis, computer use, research and agentic tasks where additional reasoning changes the outcome enough to justify the higher unit cost.

CHOOSE TERRA

Balanced production workloads

Use Terra when the application needs strong reasoning but does not consistently benefit from Sol’s extra capability. It is the natural tier to evaluate for everyday production routing.

CHOOSE LUNA

High-volume efficiency

Use Luna for classification, extraction, focused transformations and other repeatable workloads where throughput and price matter more than maximum reasoning depth.

USE GPT-6 INSTEAD

When you need the newer frontier

GPT-6 is OpenAI’s newer generation. For new high-capability systems, compare GPT-5.6 against GPT-6 rather than assuming the older family remains the best quality choice.

MIGRATION

Moving from GPT-5.5 or GPT-5.4.

OpenAI recommends beginning with your current reasoning setting rather than automatically raising effort on GPT-5.6. Test the same setting and one level lower on representative workloads, then compare quality, latency and token use.

For applications that use tools or multi-step reasoning, migration is also a chance to move toward the Responses API and evaluate persisted reasoning, Programmatic Tool Calling and beta multi-agent orchestration. Do not change model, API architecture and agent permissions all at once unless you can isolate the effect of each change in evaluation.

Older GPT-5 and o3 snapshots are also on a published deprecation path, with OpenAI listing GPT-5.6 Sol, Terra and Luna as replacement directions for several older GPT-5 tiers.

MIGRATION CHECK Evaluate on production-like tasks.

Compare acceptance rate, token usage, latency, tool errors and human correction—not only a general benchmark score.

LIMITS & CAVEATS

What to keep in mind.

01GPT-6 is newer.

GPT-5.6 remains useful, but “latest” and “highest capability” now refer to the GPT-6 generation for many workloads.

02Long context is not free context.

A 1.05M-token window is a capacity limit, not a reason to send unnecessary data. Very long prompts cost more and can increase latency.

03Benchmarks are workload-specific.

OpenAI’s launch evaluations are useful evidence, but production routing should still be based on your own task distribution and acceptance criteria.

04Tool access changes the risk model.

Agents that can browse, execute code, use MCP or call business systems need permission, sandboxing and approval controls around the model.

05Pricing can change.

Sol is explicitly on promotional pricing at the time of verification, so production cost models should reference the current official model page.

06Fine-tuning is not listed.

The current Sol model page lists fine-tuning as unsupported; use prompting, tools, retrieval and model routing where appropriate instead of assuming a fine-tuned GPT-5.6 endpoint exists.
