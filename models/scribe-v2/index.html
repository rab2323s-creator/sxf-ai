01 / THE SXF VERDICT

Excellent features on paper. Prove transcript quality on your audio.

ElevenLabs Scribe v2 is the provider's multilingual recorded-file speech-to-text model. Its API provides transcript text, word timing, optional speaker diarization and audio-event labels. It also supports keyterm prompting for specialist vocabulary and processing workflows for recorded meetings, interviews, podcasts and video. The documented identifier is scribe_v2 at POST /v1/speech-to-text.

SXF / DECISION NOTE

Choose a batch model when you need an annotated transcript after recording. Choose a real-time model when you need streaming recognition during the call. If your audio is clinical or contains regulated information, review the separate Scribe v2 Medical model and account-level protections rather than assuming Scribe v2 is designed for your compliance requirements.

The published marketing claim of over 98% transcription accuracy is provider-reported. It is not a guarantee for accented dialogue, Arabic dialects, noisy calls, specialist terms or overlapping speakers. SXF recommends evaluating WER, speaker assignment and timestamp drift on an annotated, representative test set before procurement.

03 / WORKFLOW FEATURES

What makes the raw transcript useful.

01 · TRANSCRIPT TIMING

Word-level alignment

Receive start and end times for individual words. This enables subtitle editors, click-to-play transcripts and searchable speech archives. Verify alignment at speaker changes and after long pauses.

02 · CONVERSATIONS

Speaker diarization

Assign labels to speaker segments with diarize=true. The API accepts a known maximum of 1–32 speakers. Diarization identifies speaker turns; it does not establish a real person's identity.

03 · DOMAIN VOCABULARY

Keyterm prompting

Supply product names, medical vocabulary or technical terms as hints. Up to 1,000 entries are documented, with per-term constraints. Measure both correct recall and accidental over-insertion.

04 · AUDIO CONTEXT

Non-speech event tags

Optional audio event labels can annotate laughter or other sounds. Editorially review tags before using them as ground truth in legal, investigative or sensitive content.

05 · CHANNEL ISOLATION

Multichannel recordings

Transcribe up to five input channels independently and request separate or time-sorted combined output. This can simplify call-center recordings where each party is recorded on its own channel.

06 · OPERATIONS

Asynchronous workflows

Send longer jobs to configured webhooks where appropriate. Correlate results with request metadata and implement secure verification and retry handling in your server.

Which audio should be tested first?

Start with low-quality phone audio, speakers interrupting each other, multilingual conversations and industry-specific names. These cases expose errors that a clean podcast sample may hide. Test language hints against automatic detection, and decide whether to keep verbatim filler words using no_verbatim.

05 / API INTEGRATION

From recorded file to timestamped transcript.

ElevenLabs provides a multipart POST endpoint with the model ID scribe_v2. Keep the API key on your server. The minimal example below uses an existing file named interview.mp3 and enables speaker labels; it does not require a client-side key or upload audio to SXF.

export ELEVENLABS_API_KEY="YOUR_SERVER_SIDE_API_KEY"

curl -X POST "https://api.elevenlabs.io/v1/speech-to-text" \
  -H "xi-api-key: $ELEVENLABS_API_KEY" \
  -F "file=@interview.mp3" \
  -F "model_id=scribe_v2" \
  -F "diarize=true" \
  -F "timestamps_granularity=word"

Example syntax follows the public create-transcript endpoint. Protect credentials in environment secrets; do not put a permanent API key in front-end code or a publicly shared document.

How to interpret the response

The response includes the transcript text and can include a words array with word-level start, end, text and speaker_id fields. The simplified sample below demonstrates the data shape, not an actual recorded API result.

{
  "language_code": "en",
  "text": "Welcome to the demo.",
  "words": [
    {
      "text": "Welcome",
      "start": 0.0,
      "end": 0.52,
      "speaker_id": "speaker_0",
      "type": "word"
    }
  ]
}

Production processing checklist

  1. Normalize metadata. Capture duration, sample rate, channel count, source language assumptions and consent information without needlessly copying sensitive content.
  2. Choose the right ingestion mode. Use a direct upload or the documented source_url. Avoid newly building on the deprecated cloud_storage_url parameter.
  3. Set features deliberately. Select diarization, timestamps and domain vocabulary only where justified. Some combinations are mutually exclusive.
  4. Validate the result. Check response shape, missing timestamps, speaker consistency, hallucinated tokens during silence and incorrect named entities.
  5. Store responsibly. Protect transcript access, enforce deletion or retention policy, and avoid embedding speaker identity assumptions into automation.
  6. Track operational errors. Instrument retries, throughput, p95 completion time, failures by language, downstream correction effort and cost per accepted transcript.

06 / SXF ORIGINAL EVALUATION DESIGN

How to test recognition quality without invented benchmarks.

A credible speech-recognition recommendation requires reproducible measurements on the same audio, not vendor benchmarks pasted into a table. SXF's proposed evaluation protocol below is a transparent research design; the page does not claim SXF has run independent experiments or established superiority.

EVIDENCE STATUS: REPRODUCIBLE TEST DESIGN, NOT MEASURED RESULTS

Collect a consented, human-checked set of recordings. Run each candidate with pinned versions and identical preprocessing. Score raw accuracy and downstream usability separately. Publish corpus characteristics, date, language mix and statistical uncertainty with any future results.

Suggested sample design

Use separate groups for clean studio interviews, noisy mobile audio, regional accents, cross-talk, domain jargon and mixed-language recordings. Maintain a blind manual reference and pre-register normalization rules for punctuation, numerals and filler words. Measure per-language results rather than hiding underperforming groups in a global mean. Report sample size and confidence intervals when publishing comparative numbers.

08 / SECURITY & LIMITATIONS

Accurate transcription is only one part of a trustworthy pipeline.

DATA HANDLING

Privacy and retention

Voice recordings may contain personal or regulated information. Review retention terms, encryption, deletion policy, access logs and any required data-processing agreement. The API documents enable_logging=false zero-retention mode for eligible enterprise users.

OUTPUT LIMITATIONS

Attribution is not identity

A speaker label is an algorithmic segment label, not authentication. Avoid high-stakes attribution based only on diarization. Human-review confidence and overlap cases.

CONTENT CONTROL

Verbatim versus edited

Keep the untouched raw transcript for auditability where appropriate. no_verbatim may omit fillers, and transcript editing changes the output; the two are not neutral evidence-preserving operations.

PRODUCTION SAFETY

Resilience and exceptions

Use server-side authentication, bounded retries, webhook signature checks, upload limits, rate limiting and redaction controls. Ensure transcription errors cannot trigger destructive actions without review.

IMPORTANT PRODUCT DISTINCTION

Scribe v2 performs speech recognition. It does not generate a spoken voice. For synthesis, examine ElevenLabs' text-to-speech line; for live speech recognition, examine the separate Realtime model. For legal or clinical records, human verification and applicable governance are essential.

09 / FREQUENT QUESTIONS

Scribe v2 questions answered directly.

What is ElevenLabs Scribe v2?

Scribe v2 is a multilingual speech-to-text model for transcribing recorded audio and video. The API model ID is scribe_v2 and the file-transcription endpoint is POST /v1/speech-to-text. It is not a text-to-speech or live-streaming model.

How much does Scribe v2 cost?

The public ElevenLabs API pricing page lists $0.22 per audio hour for Scribe v2, $0.05 per hour for optional keyterm prompting and $0.07 per hour for transcript editing. Multichannel processing bills each channel separately at the full audio duration. Verify your plan and current rates.

Does Scribe v2 support speaker diarization?

Yes. Set diarize=true to request speaker annotations. The API supports num_speakers from 1 to 32. Speaker IDs indicate inferred speaker turns and should be reviewed on overlapping speech.

Can Scribe v2 generate word-level timestamps?

Yes. The API supports word-level timestamps and a character-level option. The response can include start and end time per word, which can support subtitles and audio search.

Which languages does Scribe v2 support?

ElevenLabs advertises support for more than 90 languages. Actual recognition accuracy varies by language, accent, recording conditions, vocabulary and code-switching; evaluate on representative samples.

What are the file upload limits?

The current POST /v1/speech-to-text reference states that a direct file must be under 5 GB and audio must be at least 100 ms. Check the current documentation for source URLs, plan limits and other constraints.

How does Scribe v2 compare with Scribe v2 Realtime?

Scribe v2 targets recorded-file transcription via POST /v1/speech-to-text, at a listed $0.22 per audio hour. Scribe v2 Realtime is a separate streaming model with a distinct WebSocket flow and a listed $0.39 per audio hour.

What is keyterm prompting and when should I use it?

The keyterms field lets you supply specialized words and names to bias recognition. The documented limit is 1000 keyterms, each at most 50 characters or five words. Test term recall and false positives against a control set; it is a paid option.

Can Scribe v2 transcribe multiple audio channels?

Yes. use_multi_channel=true transcribes up to five channels independently. You can receive separate channel transcripts or a combined time-sorted result. Billing scales with channel count and transcript editing cannot be combined with multichannel mode.

How can I evaluate transcription accuracy fairly?

Measure word error rate on human-reviewed reference transcripts, plus speaker attribution, timestamps, entity handling, language-specific errors, latency and cost. Compare the same audio corpus and preprocessing settings for every candidate.
