TECHNICAL ANALYSIS / 01

What is being retired in VS Code 1.146?

The Local harness is an older component coordinating the model, context and tools for Copilot agent sessions inside VS Code. GitHub says the replacement Copilot harness became the default for new sessions starting with version 1.143; version 1.146 marks the older target deprecated, and removal is scheduled for February 2027.

A harness is not a model and the deprecation is not an instruction to uninstall VS Code. Developers can continue running commands on their own machine, and their files are not automatically migrated to a remote cloud simply because they choose the newer session target. This is distinct from the November 16 retirement of particular Copilot models.

TECHNICAL ANALYSIS / 02

How do you switch from Local to the Copilot harness?

GitHub instructs users who still select Local to start a new agent session and choose Copilot under Session Target. Before February 2027, compare the new session's tools, approvals and instruction files with the workflow you currently depend on. Do not assume every customization is transformed automatically between runtime targets.

For an administrator, check whether vscode.temporaryDefaultToLocalHarness is enforced through a managed configuration. That exception will not preserve the old harness after its removal. A staged rollout with a known task list is safer than changing the default for every developer without testing the connected editor tools and required enterprise permissions.

TECHNICAL ANALYSIS / 03

What changes with the Copilot harness—and what does not?

The newer harness uses a runtime shared with Copilot CLI and the GitHub Copilot app, and supports sessions that can continue between the editor and Agents window while Agent Host remains active. GitHub also points to optional capabilities such as Fusion-assisted model choice, managed permission handling, preview connectors and interactive task canvases.

Those capabilities are subject to entitlement, policy and feature availability. Crucially, GitHub says selecting Copilot does not turn on a sandbox. Organizations need to configure and verify runtime permissions and sandbox restrictions separately; sensitive repositories should keep human review and limits on destructive tool operations.

TECHNICAL ANALYSIS / 04

SXF migration test plan for a development team

Choose a representative branch and a bounded set of tests: ask an agent to summarize a repository, apply a small fix, run tests, request a tool call it should not approve automatically, and reopen or continue its session. Compare permissions, task completion, modifications and any custom instruction behavior under the two targets before the retirement deadline.

Record IDE version, Copilot plan, organization policy, connector status and which commands ran locally. Preserve a rollback strategy during the transition window and a manual alternative after it closes. READER QUESTIONS

VS Code Local harness transition FAQ

When does VS Code remove the Local harness?

GitHub specifies February 2027, after deprecation in VS Code 1.146.

Does the Copilot harness run my code in the cloud?

Selecting the Copilot harness does not by itself move local files to the cloud. VS Code can still run agent commands locally.

Will switching automatically enable sandbox protection?

No. GitHub says runtime permissions and sandbox restrictions require separate configuration.

LIMITATIONS

The announcement sets a future removal date and describes product behavior as of VS Code 1.146. It does not guarantee that every legacy customization will be converted automatically, every connector is generally available, or all features are included on Free. Actual tool permissions and sandbox enforcement depend on separate configuration.
