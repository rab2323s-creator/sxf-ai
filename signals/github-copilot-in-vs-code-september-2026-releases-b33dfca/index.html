GitHub Copilot in VS Code: September 2026 agent updates

GitHub’s September 2026 Copilot releases for Visual Studio Code, spanning VS Code 1.136 through 1.140, pushed the Agents window beyond interactive coding toward a fuller agent workflow. The month added scheduled automations, agent-assisted pull request merge work, Dev Container sessions, HydraFusion orchestration, richer GitHub context, and continuity between ChatGPT Codex conversations and VS Code.

SOURCEGitHub
PUBLISHEDOctober 1, 2026
REVIEWED2026-10-04
STATUSPublished

WHAT CHANGED

Across VS Code 1.136 through 1.140, GitHub added a sequence of agent-workflow features rather than one isolated Copilot update. Agent Merge entered public preview to handle review feedback, failed checks, merge conflicts, and workflow reruns. Automations added hourly, daily, weekly, and on-demand recurring tasks. Dev Container sessions brought project-configured tools and dependencies into the Agents window, pull requests could be created directly from Copilot, Claude, or Codex sessions, and HydraFusion reached VS Code as a research preview for selecting multi-model workflows.

WHY IT MATTERS

The September releases move GitHub Copilot closer to an end-to-end development workflow that can keep context across implementation, environment setup, pull request creation, review, checks, and follow-up work. For developers, the important change is not a single model upgrade; it is the growing coordination layer around agents. For engineering leads, that makes preview status, permissions, environment configuration, review policy, and automation scope more important because the agent can participate in more stages of the software delivery loop.

PRICING / CAPABILITY IMPACT

This release sequence is primarily a capability and workflow expansion. GitHub is giving Copilot agents more ways to schedule work, operate inside project environments, create and advance pull requests, carry context across sessions and applications, and coordinate model workflows. The practical impact depends on which preview features a user or organization enables and how much authority teams allow agents to exercise around repositories, checks, and pull requests.

WHO SHOULD CARE

VS Code developers using GitHub Copilot agents, engineering leads managing pull request and CI workflows, platform teams maintaining Dev Container environments, and organizations deciding which preview agent capabilities to enable should care most. The release affects how work is scheduled, how agents receive repository context, how sessions move across environments and apps, and how far an agent can participate in the pull request lifecycle.

WHAT TO VERIFY

Before production use.

  1. Confirm the VS Code version required for the feature you plan to use; HydraFusion specifically requires VS Code 1.140 or later according to GitHub’s release note.
  2. Check whether preview or research-preview features are enabled for your Copilot plan and whether an organization or enterprise administrator must allow them.
  3. Validate the repository and permission scope used by automations and Agent Merge before enabling recurring or pull-request-changing workflows.
  4. For Dev Container sessions, confirm Docker availability and that the repository has a supported Dev Container configuration with the required tools and dependencies.
  5. Test how your team wants humans to review agent changes, CI fixes, review responses, and final merge decisions before making Agent Merge part of a standard delivery process.
