GPT-6.1 Sol: pricing, specs, benchmarks and availability

GPT-6.1 Sol is OpenAI’s upgraded Sol model for complex coding, computer use, professional work, and agentic workflows. It keeps the Sol price tier for standard input and output tokens while cutting cached-input cost, adds stronger benchmark performance across several demanding tasks, and is positioned as the lower-cost alternative when teams want performance closer to GPT-6 Astra without paying Astra’s standard token rates.

SOURCEOpenAI
PUBLISHEDSeptember 29, 2026
REVIEWED2026-10-04
STATUSPublished

WHAT CHANGED

OpenAI introduced GPT-6.1 Sol on September 29, 2026 as an upgrade to GPT-6 Sol. The new model targets the same broad class of demanding coding and agentic work but improves capability across software engineering, professional document tasks, multi-step business workflows, computer use, scientific workflows, factuality, and alignment evaluations. OpenAI also cut cached-input pricing from GPT-6 Sol’s documented $0.20 per million tokens to $0.10 for GPT-6.1 Sol while keeping standard input at $2 and output at $10 per million tokens.

WHY IT MATTERS

GPT-6.1 Sol changes the model-selection tradeoff inside the GPT-6 family. Teams that previously had to choose between GPT-6 Sol’s lower cost and GPT-6 Astra’s stronger performance now have a model OpenAI says approaches Astra on several complex workloads at materially lower cost. The release is especially relevant for agents that reuse large amounts of context, because cached input is cheaper than on GPT-6 Sol, and for production teams that need tool calling, computer use, code execution, MCP, or long-context work without moving to Astra pricing.

PRICING / CAPABILITY IMPACT

At standard API rates, GPT-6.1 Sol costs $2 per million input tokens and $10 per million output tokens versus $10 and $50 for GPT-6 Astra in OpenAI’s launch comparison. That is one-fifth of Astra’s standard input and output token prices. Cached input is $0.10 per million tokens for GPT-6.1 Sol, compared with $0.20 for GPT-6 Sol and $1.00 for Astra in the same launch material. For agent workflows that repeatedly reuse context, the cached-input reduction can matter independently of the headline input/output rates.

WHO SHOULD CARE

API teams running coding or agent workflows, developers using computer-use or tool-calling systems, organizations processing complex professional documents, and Work or Codex users choosing between Sol and Astra should care most. GPT-6.1 Sol is particularly relevant when the workload needs more capability than GPT-6 Sol but the cost profile of Astra is difficult to justify at production scale.

PRACTICAL TAKEAWAYS

What to do with the information.

Benchmark GPT-6.1 Sol against Astra on your own complex tasks rather than assuming the cheaper model is always sufficient; OpenAI itself recommends comparing the quality-versus-cost tradeoff on real workloads.

Source 1 ↗Source 2 ↗

For agent systems that reuse large prompts, files, or instructions across requests, include cached-input volume in cost estimates because GPT-6.1 Sol’s $0.10 cached-input rate is half GPT-6 Sol’s documented rate.

Source 1 ↗Source 2 ↗

Use the Responses API when the workflow requires tools such as computer use, web search, hosted shell, code interpreter, MCP, or apply patch; do not design a tool-heavy deployment around Chat Completions for this model.

Source 1 ↗Source 2 ↗

Do not migrate from GPT-6 Sol only on benchmark headlines. Validate latency, reasoning-effort settings, tool behavior, factuality, and total cost per completed task under the same prompts and environment your production system uses.

Source 1 ↗Source 2 ↗

For Work or Codex deployments, verify plan eligibility and workspace permissions before standardizing GPT-6.1 Sol as a team default, because model availability can depend on rollout access and administrator settings.

Source 1 ↗

WHAT TO VERIFY

Before production use.

  1. Confirm that gpt-6.1-sol is enabled for the API project, ChatGPT plan, or workspace where you intend to deploy it.
  2. Benchmark GPT-6.1 Sol against both GPT-6 Sol and GPT-6 Astra using the same prompts, tools, reasoning effort, and acceptance criteria used in production.
  3. Estimate standard input, cached input, and output separately; repeated-context agent workloads may benefit disproportionately from the lower cached-input price.
  4. Check whether your workflow requires tool calling, because OpenAI directs GPT-6.1 Sol tool use through the Responses API rather than Chat Completions.
  5. Review the current model and safety documentation for residency, safeguard, and capability restrictions before deploying high-impact or security-sensitive agent workflows.
